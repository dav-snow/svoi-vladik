# Как работать втроём

Подробное распределение — [docs/TEAM.md](docs/TEAM.md) (исторический план),
актуальные задачи — [docs/BACKLOG.md](docs/BACKLOG.md), состояние —
[docs/STATUS.md](docs/STATUS.md). Проект вырос из 36-часового вайбатона;
дедлайн и правило «останавливаем функции к H27» больше не действуют.

1. Согласуйте владельца задачи и её критерий готовности. Берите одну основную задачу за раз.
2. Обновите локальный `main` и создайте ветку, например `frontend/task-022-redesign` или `docs/status-refresh`.
3. Делайте небольшие коммиты. Чужие несвязанные файлы не меняйте. Стыки API согласуйте до реализации, меняйте документ и примеры вместе с кодом.
4. Откройте PR в `main`; заполните шаблон, укажите задачу и проверку. Для интерфейса добавьте скриншот, для данных — ссылки и дату сверки.
5. Другой участник проверяет результат. Исправьте замечания и конфликты, повторите затронутые проверки, затем объединяйте PR.

Участник 1 совмещает дизайн и фронтенд: отвечает за интерфейс, интеграцию и сборку. Участник 2 отвечает за схемы, импорт данных и сервер. Участник 3 ведёт сценарий, источники и тексты, ручную приёмку и рассказ на защите. Карточки и материалы он может передавать таблицей и документом без кода; бэкендер переносит их в согласованный формат данных. Подробное задание — [ROLE_3](docs/ROLE_3.md).

При ревью бэкендер проверяет подключение API, участник 1 — удобство и отображение данных, участник 3 — сценарий и соответствие первоисточникам. Исторические факты и условия бесплатности дополнительно сверяет другой участник. Каждый PR проверяет кто-то, кроме автора. Правило ревью пока командная договорённость; автоматическая защита ветки не настроена.

До параллельной работы согласуйте API и общие примеры. Клиент — `frontend-design/dist/` (правится напрямую, без сборщика); бэкенд — `backend/`, серверные зависимости и общий конфиг размещения. Участник 3 ведёт исходную таблицу/тексты; машинный JSON импортирует участник 2. В одном наборе файлов работает только один человек или ИИ-агент; для отдельной параллельной задачи нужен другой набор файлов или отдельный worktree с последующим объединением. После правок `dist/` пересчитайте `build-manifest.json` командой `node scripts/build.mjs`.

Не публикуйте `.env`, токены и пароли. Перед изменением конфигурации сохраните рабочий коммит и безопасный способ отката; секретные значения в Git не копируйте. Новые зависимости проверяйте по официальному проекту и фиксируйте версии. Указывайте источники контента и происхождение внешних материалов. Журнал работы с ИИ ведите в [AI_USAGE](docs/AI_USAGE.md), минимальные требования — [SECURITY](docs/SECURITY.md), выпуск — [RELEASE_CHECKLIST](docs/RELEASE_CHECKLIST.md).
