# Как работать втроём

Подробное распределение — [docs/TEAM.md](docs/TEAM.md), задачи — [docs/BACKLOG.md](docs/BACKLOG.md).

1. Согласуйте владельца задачи и её критерий готовности. Берите одну основную задачу за раз.
2. Обновите локальный `main` и создайте ветку, например `feat/SV-06-places` или `docs/SV-03-sources`.
3. Делайте небольшие коммиты. Чужие несвязанные файлы не меняйте. Стыки API согласуйте до реализации, меняйте документ и примеры вместе с кодом.
4. Откройте PR в `main`; заполните шаблон, укажите ID задачи и проверку. Для интерфейса добавьте скриншот, для данных — ссылки и дату сверки.
5. Другой участник проверяет результат. Исправьте замечания и конфликты, повторите затронутые проверки, затем объединяйте PR.

Дизайнер проверяет сценарий и тексты, бэкендер — схемы, данные и сервер, фронтендер — интеграцию, сборку и демо. Правило ревью пока командная договорённость; автоматическая защита ветки не настроена.

Не публикуйте `.env`, токены и пароли. Указывайте источники контента и происхождение внешних материалов. Журнал работы с ИИ ведите в [AI_USAGE](docs/AI_USAGE.md).
