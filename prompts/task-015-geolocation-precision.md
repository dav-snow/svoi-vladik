# Задача 015: точная геолокация и честная точность

Фронтовая задача. Меняем только клиент. Бэкенд, API, данные, Docker — не трогать.

## Контекст

«Свой Владик» — FastAPI + buildless-фронт на MapLibre. Фронт правится напрямую в
`frontend-design/dist/`: `app.js` (вся логика), `index.html` (разметка),
`styles.css` и остальные CSS. Отдельной сборки нет; `node scripts/build.mjs`
только пересчитывает хэши в `build-manifest.json`.

Документы-источники:

- `prompts/FRONTEND_TODO.md`, пункт 1 — постановка и критерий.
- `docs/GEOLOCATION.md` — правила геолокации и приватности.
- `INTEGRATION.md`, `docs/API.md` — контракт API.

Текущая база — ветка `frontend/real-api-ux-check-20261114` (+8 к `origin/main`):
в ней уже влиты онбординг Влады, галерея фото и практический гид. Если `main`
уже обновлён — базируйся на `main`.

## Что уже работает (не переделывать)

- Одноразовый `navigator.geolocation.getCurrentPosition`, без `watchPosition` и
  фоновых повторов; запрос только по явному клику.
- Защита от устаревших ответов: `geo.reqId`, поздний callback игнорируется.
- Состояния `idle/requesting/ready/denied/unavailable/timeout`.
- Маркер «Вы здесь» для GPS и «Выбранная точка» для ручного ввода.
- Ручной ввод: координаты lat/lng в диалоге `firsttime-dialog`, выбор места из
  каталога, кнопка «Выбрать как старт».
- Расстояние по хаверсинусу, фильтр `distanceM <= radiusM`, сортировка по
  возрастанию с устойчивым тай-брейком по `id`.
- Радиус 300–5000 м, по умолчанию 1000; смена радиуса не делает новый запрос.
- Координаты нигде не сохраняются и не отправляются — это закреплено тестами.

## Что не так сейчас

1. Запрос идёт с грубыми настройками (`frontend-design/dist/app.js`,
   функция `requestNearby`):

   ```js
   }, { enableHighAccuracy: false, timeout: 10000, maximumAge: fresh ? 0 : 60000 });
   ```

   Первый запрос разрешает кэш до 60 секунд, высокая точность выключена —
   отсюда «рядом» показывает не те места.

2. Предупреждение о плохой точности появляется только когда `accuracyM >
   radiusM` **и** включён фильтр радиуса. При радиусе 5 км предупреждения нет
   вообще, даже при точности 800 м. Порог 100 м из постановки не реализован.

3. В `updateNearbyStatus()` точность подписана «около N м»: нет явного «±», нет
   отдельной формулировки предупреждения, а при выключенном фильтре радиуса
   предупреждение исчезает.

4. Кнопка ручного старта подписана «Выбрать старт», а кнопка очистки в готовом
   состоянии — «Очистить старт» / «Отменить запрос». В постановке —
   «Выбрать вручную» и «Не использовать моё местоположение».

## Задача 1 — свежая и точная позиция

- Ввести одну константу опций рядом с геоблоком:
  `{ enableHighAccuracy: true, timeout: 15000, maximumAge: 0 }`.
- Использовать её и для первого запроса, и для «Обновить местоположение»;
  различие `fresh` (кэш 60 с) убрать. Параметр можно удалить вместе с
  аргументами у вызовов, но имена `requestNearby`, `clearNearby`,
  `setManualOrigin` сохранить — их вызывает `frontend-design/tests/geolocation.test.mjs`.
- Пока идёт запрос: кнопка «Что рядом со мной» disabled, в статусе — что это
  может занять до 15 секунд. Ручной выбор доступен всё это время.
- После любого ответа (успех, отказ, таймаут, ошибка) кнопка снова активна.
- Никаких `watchPosition`, повторов по таймеру и запросов при загрузке.

## Задача 2 — точность, время и предупреждение

Для `origin === 'device'` статус всегда содержит точность и время определения:

`Рядом со мной · 1 км · 5 из 14 мест · точность примерно ±35 м · определено в 14:32`

Предупреждение показывается, если `accuracyM > 100` **или** `accuracyM >
radiusM`, и **не зависит** от `geo.radiusFilter`: если пользователь нажал
«Показать все места» и фильтр выключен, предупреждение всё равно остаётся.

Требования:

- Радиус при плохой точности не расширять молча, `geo.radiusM` не менять.
- В предупреждении: результат приблизительный, расстояние считается по прямой,
  и два выхода — «Обновить местоположение» и «Выбрать вручную».
- Процент уверенности не показывать.
- Для ручной точки (`origin === 'manual'`): ни точности, ни времени определения,
  ни предупреждения о точности — только «Выбранная точка».
- Предупреждение — часть `#nearby-status` (у него уже `role="status"` и
  `aria-live="polite"`). Отдельный элемент не обязателен; если добавишь — сохрани
  доступность и обнови тесты.
- Смена радиуса пересчитывает статус и предупреждение без нового запроса GPS.

## Задача 3 — подписи

- `#nearby-manual`: «Выбрать вручную» (сейчас «Выбрать старт»).
- `#nearby-clear` в состоянии `ready`: ровно «Не использовать моё местоположение».
  В `requesting` допустимо «Отменить запрос»; после установки позиции — снова
  «Не использовать моё местоположение». «Очистить старт» убрать.
- `#nearby-request`: «Что рядом со мной» — не менять.
- `#nearby-refresh`: «Обновить местоположение», видна только при GPS-позиции —
  не менять.
- Остальные тексты (юмор Влады, подсказки) без нужды не переписывать.

## Задача 4 — тесты

Обнови `frontend-design/tests/geolocation.test.mjs`, не ослабляя существующие
проверки, и добавь случаи:

1. `requestNearby` передаёт ровно
   `{enableHighAccuracy: true, timeout: 15000, maximumAge: 0}`.
2. Точность 350 м при радиусе 1000 м: в статусе есть «приблизительный» и «±»,
   `geo.radiusM` не изменился.
3. Точность 35 м: предупреждения нет, «±35 м» есть.
4. Ручная точка: «Выбранная точка», нет слова «точность» и предупреждения.
5. Предупреждение остаётся после `toggleRadiusFilter()`.
6. Старые инварианты: координаты не попадают в storage/URL/сеть, поздний callback
   игнорируется, отказ/таймаут оставляют ручной старт.
7. `clearNearby()` по-прежнему отменяет запрос и убирает маркер.

Тесты синтетические (заглушка `navigator`), настоящий GPS не используется.
В существующем тесте «latest lookup wins» ожидания `maximumAge`/`timeout`
замени на новые.

## Приватность и честность (обязательно)

- Координаты, точность и время — только в памяти страницы. Не писать в
  `localStorage`, URL, API, `console`, логи, скриншоты, коммиты.
- Не подставлять центр района как «текущую позицию».
- Не обещать точность: `accuracy` — оценка позиции, а не расстояния до места.
- В отчёте честно указать, что проверка на реальном телефоне не выполнялась,
  если она не выполнялась; проверялись синтетические позиции/DevTools.
