# Задача 014: рабочая ссылка в 2ГИС, время пешком и ручная точка

Фронтовая задача. Бэкенд уже готов (см. «Что готово на бэкенде»). Менять только
`frontend-design/dist/app.js`, `index.html`, `styles.css`. API и данные — не трогать.

## Проблема 1 — 2ГИС не подставляет адрес назначения

Сейчас `app.js` собирает ссылку сам:

```js
function routeURL(place) { return `https://2gis.ru/directions/tab/pedestrian/points/%7C${place.lng},${place.lat}`; }
```

`%7C` — это закодированный `|`. 2ГИС разбирает **сырой** путь и ожидает
литеральный `|` как разделитель «старт|финиш». Из-за `%7C` финиш отбрасывается,
2ГИС открывается, но точка Б пустая. Это и есть баг.

Официальный формат:
`https://2gis.ru/directions/tab/pedestrian/points/|<lon>,<lat>`
(пустой старт = текущее местоположение пользователя, финиш = точка).

## Что готово на бэкенде

Каждый объект места в `GET /api/v1/places` (и в `GET /api/v1/places/{id}`) теперь
содержит готовое поле **`route_url`**:

```json
{
  "id": "sukhanov-house",
  "coordinates": { "lat": 43.1172756, "lng": 131.8949904 },
  "route_url": "https://2gis.ru/directions/tab/pedestrian/points/|131.8949904,43.1172756"
}
```

`route_url` уже с литеральным `|`, без `%7C`. Собирать ссылку на клиенте больше
не нужно.

## Задача 1 — использовать route_url

- Удалить `routeURL(place)` (или сделать её `return place.route_url`).
- Во всех кнопках «Пешком в 2ГИС» / «Идти в 2ГИС» / «К остановке в 2ГИС» брать
  `place.route_url` как есть. **Не** пропускать через `encodeURIComponent`.
- Для остановок прогулки и квестов: найти место по `place_id` в `state.places`
  и взять его `route_url`.
- Если `route_url` нет (теоретически) — не показывать кнопку.

## Проблема 2 — нет времени пешком

Расстояние «≈350 м по прямой» есть, а сколько идти — нет.

## Задача 2 — примерное время пешком

Расстояние уже считается хаверсинусом (`haversineM`) в памяти. Добавить время:

- Скорость пешехода для оценки: `80` м/мин (≈4.8 км/ч).
- `minutes = Math.round(distanceM / 80)`.
- В карточке рядом с расстоянием: `≈350 м по прямой · ~4 мин пешком`.
- Подпись оговорки один раз в карточке/легенде: «время приблизительное, по
  прямой, без учёта маршрута».
- Считать только при наличии позиции (`geo.origin`). Без позиции — только
  расстояние не показываем вовсе (как сейчас).
- Сортировку и фильтр радиуса не менять — они уже по `distanceM`.

## Проблема 3 — геолокация плохо работает

Ручной старт частично есть (`geo.origin = 'manual'`, кнопка «Выбрать как старт»,
`#nearby-manual`). Нужно довести до полноценного ввода.

## Задача 3 — указать своё местоположение вручную

- В блоке «Что рядом со мной» добавить ручной ввод: координаты `lat`/`lng`
  (два числовых поля) **или** выбор точки кликом по карте. Достаточно одного
  простого способа, но обязательно с валидацией: lat −90…90, lng −180…180.
- Установка ручной точки: `geo.origin='manual'`, `geo.lat`, `geo.lng`,
  `geo.accuracyM=null`, `geo.capturedAt=null`, `geo.radiusFilter=true`, затем
  `renderPlaces()` и подпись маркера «Выбранная точка» (не «Вы здесь»).
- После ручной точки список/расстояния/время работают так же, как с GPS.
- «Не использовать моё местоположение» очищает и ручную точку.
- Кнопка «Обновить местоположение» при ручном origin не должна молча
  перезапрашивать GPS без явного действия пользователя.

## Приватность (обязательно)

- Координаты пользователя **не** уходят в API, URL, `localStorage`, логи,
  `console`.
- Ручная точка живёт только в памяти страницы.
- `writeStorage` для геоданных не использовать.

## Критерий приёмки

- `node --check frontend-design/dist/app.js` проходит.
- Кнопка 2ГИС открывает пешеходный маршрут с заполненным финишем (точка Б).
- При известной позиции в карточке: расстояние и «~N мин пешком».
- Можно ввести свою точку вручную; появляется маркер «Выбранная точка»,
  расстояния/сортировка работают.
- Смена радиуса/категории/поиска не вызывает новый запрос геолокации.
- В DevTools → Application → Local Storage нет координат; в Network нет
  запросов с координатами.
