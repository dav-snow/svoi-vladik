# ЧАСТЬ 1. Фикс (первый коммит)

## Причина

Проверка показала: страница нового фронта грузится, но данные карты не приходят. `frontend-design/dist/app.js:265` запрашивает `data/leninsky-boundary.geojson` и `data/leninsky-poi-candidates.geojson`, а смонтированный `/data` указывает на репозиторные `data/geo` и `data/examples`. Оба запроса фронта получают 404, страница показывает «Не удалось загрузить места». Существующий тест этого не ловит, потому что проверяет `/data/geo/leninsky-boundary.geojson` — путь, который фронту не нужен.

## Что сделать

1. **[БЛОКЕР] `/data` должен отдавать данные фронта.**
   Смонтировать `frontend-design/dist/data` под `/data`. Ожидаемо:
   - `GET /data/leninsky-boundary.geojson` → 200, тело GeoJSON;
   - `GET /data/leninsky-poi-candidates.geojson` → 200, тело GeoJSON.
   Репозиторные `data/geo` и `data/examples` публично больше не раздавать: их не использует ни один клиент. Отдельный префикс для них не добавляй.

2. **Переписать тест статики под реальные нужды фронта:** оба файла отдают 200 и валидный JSON (`json.loads` проходит, `"type": "FeatureCollection"`). Старый путь `/data/geo/leninsky-boundary.geojson` как рабочий не тестировать. Тест должен падать, если `/data` снова укажет не туда.

3. **`INTEGRATION.md`, раздел «Статика и один origin»:** `/data` — это данные дизайн-фронта (граница и точки-кандидаты). Убери утверждение, что `/data` отдаёт `data/geo` и `data/examples`.

4. **[БАГ] Локализовать `message`.** Сейчас `/api/v1/nope` отдаёт `"Not Found"`, `POST /api/v1/places` — `"Method Not Allowed"`, хотя `INTEGRATION.md` обещает русский текст. Если `exc.detail` — обычная строка (а не наш dict), не тащить её в ответ, а брать дефолт из `_DEFAULT_ERRORS` по статусу. 405 от этого не сломается — он тоже приходит строкой.
   Ожидаемо: `/api/v1/nope` → `NOT_FOUND` + «Ресурс не найден»; `POST /api/v1/places` → `METHOD_NOT_ALLOWED` + «Метод не поддерживается». Наши явные сообщения (место не найдено, неверный формат `place_id`) остаются как есть.

5. **[ТЕСТ] Усилить проверку OpenAPI:** сравнивать точный набор путей
   `{"/health", "/api/v1/places", "/api/v1/places/{place_id}", "/api/v1/walks", "/api/v1/quest", "/api/v1/test-empty", "/api/v1/test-error"}`.

6. **[ТЕСТ] 500.** Добавить проверку: непойманное исключение → 500 `INTERNAL_ERROR`, тело без текста исключения и трассировки. Через `TestClient(app, raise_server_exceptions=False)` и `monkeypatch` загрузчика на `raise`. Если без костылей в прод-код не выходит — не добавляй костыли, напиши в «Отклонениях».

7. **[ДОК] `README.md`.** Команда `python3 -m venv .venv` на машине не работает (`python3-venv` не установлен). Замени на запуск тестов в контейнере:
   `docker run --rm -v "$PWD":/src -w /src/backend python:3.11-slim sh -c "pip install -q -r requirements-dev.txt && python -m pytest -q"`
   Эта команда проверена и проходит. `open http://localhost:8000/` — macOS-специфично, замени на нейтральное «открыть в браузере».

# ЧАСТЬ 2. GPS «Вы здесь» (второй коммит)

Источник требований — `docs/GEOLOCATION.md` в репозитории. Прочитай его целиком и следуй ему. Ниже — как это ложится на текущий прототип.

## Что есть сейчас

`frontend-design/dist/` — buildless прототип: `app.js` (268 строк, плотный стиль, без сборки), `index.html`, `styles.css`, данные из `data/*.geojson` (задача 1 чинит их отдачу). В `app.js`: `state` (places, map, markers, filter, query, selected, saved), `renderPlaces()`, `initialiseMap()` (MapLibre, маркеры через `maplibregl.Marker` с HTML-элементом), `showFallback()` (SVG-схема без карты), поиск и категории.

## Что требуется

1. **Кнопка «Что рядом со мной»** в блоке поиска (`index.html`, `section.search-section`), рядом с полем поиска. Никакого автоматического запроса геолокации при загрузке страницы — только по нажатию.
2. **Одноразовый запрос** через `navigator.geolocation.getCurrentPosition` с настройками из документа: `enableHighAccuracy: false`, `timeout: 10000`, `maximumAge: 60000`; повторное явное обновление — `maximumAge: 0`. Без `watchPosition` и без фоновых повторов.
3. **Состояния:** `idle`, `requesting`, `ready`, `denied`, `unavailable`, `timeout`. Пока идёт запрос — кнопка недоступна, рядом видно подпись «Определяем местоположение…», каталог и ручные действия остаются рабочими. Каждой ошибке — понятный русский текст и предложение выбрать точку вручную либо обновить. Не подставлять центр района как «текущую позицию».
4. **Маркер «Вы здесь»** на карте: визуально отличается от маркеров мест, с подписью. Показывать точность («Точность около … м») и время определения. Ручная точка (если она есть в интерфейсе) подписывается «Выбранная точка», а не «Вы здесь».
5. **Радиус и расстояния.** Радиус 100–5000 м, по умолчанию 1000 м; управляющий элемент — на твой выбор, но простой (например select с 300/500/1000/2000/5000). Расстояние считать на клиенте по формуле хаверсинуса в метрах, фильтр по неокруглённому `distance <= radius`, сортировка по возрастанию с устойчивым порядком по `id` при равенстве. В карточке места — подпись вида «≈350 м по прямой». Округление только в подписи.
6. **Список и карта используют один результат.** Смена радиуса или категории/поиска пересчитывает по уже полученной позиции без нового запроса геолокации. Без позиции — обычный порядок каталога и никаких расстояний.
7. **Пустая выдача:** текст «В выбранном радиусе нет мест из нашего каталога Ленинского района» + подсказка увеличить радиус/выбрать вручную.
8. **Низкая точность:** если `accuracy` больше радиуса, предупредить, что результат приблизительный, и предложить обновить позицию или выбрать вручную. Радиус при этом молча не расширять.
9. **Обновление и очистка:** кнопка «Обновить местоположение» (новый запрос) и «Не использовать моё местоположение» (убрать позицию и маркер, вернуть обычный каталог).
10. **Защита от устаревших ответов:** хранить идентификатор актуального запроса, игнорировать callback, если режим сменился, позиция очищена или пришёл более новый ответ.
11. **Список работает без карты.** Если MapLibre не загрузился и показывается SVG-схема, геолокация и ближайшие места в списке продолжают работать; маркер на схеме — если получается просто, иначе только подпись в статусе.

## Приватность (из документа, обязательна)

- Координаты, точность и время позиции **не** пишутся в `localStorage`, URL, запросы к API, логи, `console`. Сырой объект `GeolocationPosition` не сериализуется.
- Позиция живёт только в памяти страницы; после перезагрузки — только новое явное действие.
- Существующий `writeStorage` трогать нельзя для геоданных; выбор аватара и закладки работают как раньше.
- Текст объяснения рядом с кнопкой: используем местоположение для поиска ближайших мест, историю перемещений не сохраняем.

## Ограничения части 2

- Не добавлять библиотеки. Только `maplibregl`, который уже подключён.
- Не подключать API — данные по-прежнему из `data/*.geojson`. Это следующая задача.
- Не переписывать `app.js` целиком: правки в существующем стиле файла (плотные однострочные функции, `el()`, `button()`, `icon()`).
- Не ломать текущие состояния: поиск, категории, закладки, офлайн-схема, мобильная нижняя панель.

## Критерий приёмки части 2

- `node --check frontend-design/dist/app.js` проходит.
- `docker compose up -d --build`, открыть `http://localhost:8000/`:
  - кнопка «Что рядом со мной» есть и до нажатия геолокация не запрашивается (в браузере нет запроса разрешения при загрузке);
  - при разрешении появляется маркер «Вы здесь», в карточках появляются расстояния, список отсортирован по возрастанию;
  - при отказе и при подмене координат на удалённые — понятное сообщение, каталог работает;
  - смена радиуса и категории не вызывает новый запрос геолокации;
  - «Не использовать моё местоположение» убирает маркер и возвращает обычный порядок;
  - в DevTools → Application → Local Storage нет координат, точности и времени позиции; в Network нет запросов с координатами.
- Тесты бэкенда остаются зелёными.
