# Фронтенд: что сделать по порядку (единый бэклог)

> Это основной список задач для фронтендера. Читай сверху вниз и отмечай `[x]`.
> Сначала P0 (баги), потом P1 (уже готовый бэкенд), потом P2.
> Новый баг — допиши в «Журнал багов» внизу, чтобы не потерять.
> Контракт API: `INTEGRATION.md` и `docs/API.md`. Сценарий Влады:
> `docs/VLADA_AND_ONBOARDING.md`. Меняем только
> `frontend-design/dist/{app.js,index.html,styles.css}`.

## Правила (не нарушать)

- Координаты пользователя **не** отправляем в API, URL, localStorage, логи,
  `console`. Позиция живёт только в памяти страницы.
- Не добавлять библиотеки; используется `maplibregl`, который уже подключён.
- Не выдумывать маршруты и точность: показываем честные оценки и ручной ввод.
- После каждого пункта должен выполняться его «Критерий».

## P0 — Баги

### [x] 1. Геолокация определяется неточно

Сейчас позиция грубая (браузер отдаёт приблизительный центр по Wi-Fi/IP),
поэтому «рядом» показывает не те места. Причина — `enableHighAccuracy: false`
и кэш позиции.

Сделать:
- Запрашивать `navigator.geolocation.getCurrentPosition` с
  `{ enableHighAccuracy: true, timeout: 15000, maximumAge: 0 }`.
- Показывать точность: «Точность примерно ±N м» и время определения.
- Если `accuracy` больше выбранного радиуса (или больше 100 м) — предупреждать,
  что результат приблизительный, предлагать «Обновить позицию» и ручной ввод.
  Радиус при этом молча **не** расширять.
- Кнопки: «Что рядом со мной», «Обновить местоположение», «Выбрать вручную»,
  «Не использовать моё местоположение».
- Без `watchPosition` и фоновых повторов. Позиция — только в памяти.
- Не подставлять центр района как «текущую позицию».
- Серверные ручки координат не принимают — расстояние и сортировка считаются
  на клиенте (хаверсинус), фильтр по `distanceM <= radiusM`, сортировка по
  возрастанию, устойчивый тай-брейк по `id`.

Критерий: на телефоне после разрешения маркер «Вы здесь» стоит рядом с реальным
местом; видна точность; при плохой точности есть предупреждение и ручной ввод;
перезагрузка страницы не показывает старую позицию без нового действия.

**Сделано в задаче 015** (`frontend/task-015-geolocation-precision`): свежие
опции `enableHighAccuracy: true, timeout: 15000, maximumAge: 0`, точность «±N м»
и время, предупреждение при `accuracyM > 100` или `> radiusM` (независимо от
фильтра радиуса), подписи «Выбрать вручную» / «Не использовать моё
местоположение», 27 синтетических тестов. Проверка на реальном телефоне ещё не
выполнена.

### [x] 2. Нельзя собрать свой маршрут (старт + добавление точек)

Сейчас можно только смотреть готовые прогулки. Нужно дать пользователю собрать
свой маршрут из мест каталога.

Сделать (клиентская функция, без изменений API):
- Выбор старта: текущая позиция (если есть), ручная точка на карте, либо любое
  место из каталога как «старт».
- На карточке места — кнопка «В маршрут» (добавить/убрать).
- Экран/панель маршрута: список выбранных точек в порядке посещения,
  перестановка вверх/вниз (или drag), удаление, «очистить».
- Показывать суммарное расстояние по прямой и примерное время пешком
  (скорость ~80 м/мин), с оговоркой «приблизительно, по прямой».
- На каждый переход — кнопка «В 2ГИС»: использовать `place.route_url`
  (готовая ссылка) или строить «из точки А в точку Б» по официальному формату
  `https://2gis.ru/directions/tab/pedestrian/points/<lngA>,<latA>|<lngB>,<latB>`.
- Сохранять собранный маршрут локально (localStorage) — переживает перезагрузку
  на устройстве. В API координаты не отправлять.
- Не выдавать это за проверенный пешеходный маршрут: это упорядоченный список
  точек + внешняя навигация на каждом переходе.

Критерий: можно выбрать старт, добавить 2–5 точек, поменять порядок, удалить,
увидеть суммарное расстояние/время и открыть переход в 2ГИС; после перезагрузки
маршрут на месте.

**Сделано в задаче 018** (`frontend/task-018-route-builder`): кнопка «В маршрут»
на карточке и в диалоге места; панель маршрута в шапке со счётчиком; старт —
«Моё местоположение», место из каталога («Сделать стартом») или ручные
координаты; 2–5 точек, порядок стрелками, удаление и очистка; сумма по прямой и
оценка ~80 м/мин; на каждый переход — 2ГИС (`route_url` при старте от позиции,
иначе A→B). В localStorage — только id мест и вид старта; ручная точка не
переживает перезагрузку (приватность). 10 синтетических тестов.

## P1 — Подключить уже готовый бэкенд

### [x] 3. 2ГИС: брать `place.route_url`, не собирать вручную
У места в API есть `route_url` с сырым `|` (не `%7C`). Использовать как есть в
кнопках «Пешком в 2ГИС»/«Идти в 2ГИС». Подробно — `prompts/task-014-*.md`.

### [x] 4. Время пешком в карточках
Рядом с «≈350 м по прямой» показывать «~4 мин пешком» (`round(distanceM/80)`),
с оговоркой о приблизительности.

### [x] 5. Ручная точка при плохой геолокации
Поля ввода `lat`/`lng` или клик по карте; маркер «Выбранная точка» (не «Вы
здесь»); после установки работают расстояния/сортировка; «Не использовать моё
местоположение» очищает.

### [x] 6. Фотографии мест (бэкенд готов)
У `Place` есть `images: [{url, alt, caption, source_url}]` (первый — обложка) и
старое `image`. Показывать галерею в карточке/диалоге места: обложка + листание,
`alt` для доступности, `caption` и ссылка на источник, если есть. Фото раздаются
с того же origin по `/media/...`. Пока фотографий может не быть — `images: []`,
тогда показывай текущую заглушку.

**Сделано:** галерея — задача 016, лицензированные фото подключены к данным —
задача 017 (16 мест, 30 изображений, `/assets/places/...`).

### [x] 7. Обучение Влады (бэкенд готов)
- `GET /api/v1/me` возвращает `onboarding` (статус прогресса).
- `GET/PUT /api/v1/me/onboarding` — чтение/частичное обновление:
  `status ∈ pending|in_progress|completed|skipped`, `step` (id шага),
  `interest ∈ places|walks|quest`.
- Показывать знакомство новому пользователю (`pending`), не показывать при
  `completed`/`skipped`; «Помощь Влады» открывает повторно (ставь `in_progress`).
- Сценарий/реплики/картинки — `docs/VLADA_AND_ONBOARDING.md`. Обучение не
  отмечает посещения и не засчитывает квест.

**Сделано** в задаче `frontend/task-00x-onboarding`; в задаче 019 исправлен
повторный «Открыть квесты/прогулки», когда список уже открыт; в задаче 020
знакомство запоминается на устройстве и не возвращается после регистрации,
обновления или выхода из аккаунта.
