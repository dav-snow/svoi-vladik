# Задача 013: вход, профиль, отметки и лайки на фронте

Делать **после** задачи 009 и **после** мержа бэкенда задачи 012.
Отдельная ветка: те же `app.js` / `index.html` / `styles.css`.

## Что уже готово на бэкенде (не менять)

| Метод | Путь | Ответ |
|---|---|---|
| POST | `/api/v1/auth/register` | `{login,password}` → 201, кука `sv_session`, `{"user":{"id","login"}}`; 409 если логин занят |
| POST | `/api/v1/auth/login` | 200 + кука; 401 при неверной паре; 429 при переборе |
| POST | `/api/v1/auth/logout` | 204, кука сбрасывается |
| GET | `/api/v1/me` | `{"user":{"id","login"}}` или 401 |
| GET | `/api/v1/me/profile` | `{"user":{...},"stats":{"visits":N,"likes":M},"visited_place_ids":[],"liked_place_ids":[]}` |
| POST/DELETE | `/api/v1/places/{place_id}/visit` | `{"visited":bool,"visits":N}` |
| POST/DELETE | `/api/v1/places/{place_id}/like` | `{"liked":bool,"likes":N}` |
| GET | `/api/v1/leaderboard?limit=10` | `{"items":[{"login","visits","likes"}],"total":N}` |

`GET /api/v1/places` и карточка места отдают `visits`, `likes`, `visited_by_me`, `liked_by_me`.

**Сессия живёт только в `HttpOnly`-куке.** Фронт не читает её, не хранит токен
в `localStorage` и ничего не шлёт вручную — запросы same-origin идут с кукой сами.

## Что сделать

1. **Вход.** Кнопка «Войти» в шапке на месте удалённой кнопки аватара.
   Диалог: поля логина и пароля, кнопки «Войти» и «Создать аккаунт», переключатель
   между режимами. Подпись: «Демо-вход без email. Не используйте реальные пароли».
   Ошибки: 401 «Неверный логин или пароль», 409 «Такой логин уже занят»,
   429 «Слишком много попыток, подождите минуту», 422 «Логин 3–32 символа, пароль от 8».
2. **Состояние входа.** После входа в шапке логин вместо «Войти». При загрузке
   приложения один раз `GET /api/v1/me`; 401 — просто гость, без ошибки в консоли.
   Кнопка «Выйти» — в профиле и в меню.
3. **Карточка места.** Два индикатора: «посетили N» и «нравится M».
   Две кнопки-переключателя: «Я был здесь» и «Нравится».
   - авторизован: состояние берётся из `visited_by_me` / `liked_by_me`,
     по нажатию POST/DELETE, счётчики обновляются из ответа;
   - гость: кнопки открывают диалог входа с подписью «Войдите, чтобы отметить»;
   - ошибка сети: сообщение и возврат состояния кнопки, без выдуманных счётчиков.
4. **Профиль.** Диалог по клику на логин: логин, «Посетил: N мест», «Лайкнул: M мест»,
   списки посещённых и лайкнутых мест по названиям из `state.places`,
   кнопка «Мой топ» и «Выйти».
5. **Топ.** Экран «Топ исследователей» из `/api/v1/leaderboard`: место, логин,
   число посещений, число лайков. Подпись: «По отметкам посещений. Демо-данные,
   визит не подтверждается». Свой логин подсветить.
6. **Обновление.** После входа и после каждой отметки перерисовать карточку места;
   профиль и топ запрашивать при открытии, не кешировать между запросами.
7. **Честные подписи.** «Посетили» — это количество отметок, а не подтверждённых
   визитов. Не писать «рейтинг достижений» и «проверенные посещения».

## Ограничения

- Разрешённые пути: `frontend-design/dist/app.js`, `index.html`, `styles.css`.
- Запрещено: `backend/**`, `data/**`, `docs/**`, `assets/**`, `mascot.js`,
  `mascot.css`, `sw.js`, `scripts/**`.
- Никаких библиотек. Пароль не сохранять ни в `localStorage`, ни в JS-переменных
  дольше отправки формы. Токен сессии во фронте не хранить вообще.
- Тексты выводить как текст. Внешние ссылки — `rel="noopener noreferrer"`.
- Сохранить `prefers-reduced-motion`, `aria-live`, `aria-pressed`, фокус в диалогах.
- Не ломать: обход и опрос квеста, GPS «Что рядом со мной», избранное, маскота, PWA.

## Критерий приёмки

- `node --check frontend-design/dist/app.js`, `npm run build`.
- Вручную на 390×844 и 1440×960:
  - регистрация → в шапке логин; перезагрузка → вход сохранился;
  - «Я был здесь» → счётчик у места вырос, повторное нажатие снимает отметку;
  - «Нравится» → счётчик лайков вырос независимо от посещений;
  - профиль показывает правильные числа и списки мест;
  - топ показывает пользователей по числу посещений, свой логин подсвечен;
  - гость нажимает «Я был здесь» → открывается вход, после входа действие не
    выполняется самовольно (пользователь нажимает ещё раз);
  - logout → счётчики у мест остаются, личные отметки исчезают, кнопки снова
    предлагают войти.
- В DevTools → Application → Local Storage нет токена сессии и пароля.
- В Network запросы идут с кукой `sv_session`, тело логина/пароля только в auth-ручках.
- Скриншоты: диалог входа, карточка с двумя счётчиками, профиль, топ.
