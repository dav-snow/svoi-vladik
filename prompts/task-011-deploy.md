# Задача 011: деплой-кит с HTTPS (без выкладки на сервер)

## Рамки

Готовим **файлы** для публичного стенда с HTTPS. Никто ничего не публикует, не
заводит аккаунты у хостинга, не вписывает реальные домены, IP и пароли.
Выкладку делает владелец руками по инструкции.

Зачем HTTPS: без него не работает геолокация в браузере, а кука сессии с флагом
`Secure` не установится — то есть вход и «рядом с точкой» на телефоне не проверить.

## Контекст

- FastAPI в `backend/main.py` отдаёт статический фронт из `frontend-design/dist/`,
  API `/api/v1/*`, два GeoJSON и `/health`.
- Есть `Dockerfile` и локальный `docker-compose.yml` (api на `127.0.0.1:8000`).
- В бэкенде есть in-memory лимитер, который считает по IP соединения и **не доверяет**
  `X-Forwarded-For`. За прокси все запросы придут с одного адреса, и лимит
  «30 запросов в минуту» станет общим на всех. Решается конфигурацией uvicorn,
  не правкой кода.
- Ветка с базой (SQLite) может появиться параллельно. В её коде появятся env `DB_PATH`
  и `COOKIE_SECURE=1`. Прод-compose обязан это поддержать, но не должен падать,
  если переменные ещё не используются.
- `data/private/quest-answers.json` — серверные ключи ответов, в git их нет.
  Без этого файла квесты отдают 503.

## Разрешённые пути

Создать/изменить только:

- `docker-compose.prod.yml`
- `Caddyfile`
- `.env.example`
- `docs/DEPLOY.md`
- `.dockerignore` (только если нужно исключить лишнее из образа)

Запрещено менять: `backend/**`, `data/**`, `docs/API.md`, `INTEGRATION.md`,
`README.md`, `frontend-design/**`, `Dockerfile`, `docker-compose.yml`,
`.github/**`, `scripts/**`, `prompts/**`.

## Что сделать

### 1. `docker-compose.prod.yml`

- `api`: сборка из `Dockerfile`, **портов наружу не публикует**, только внутренняя сеть.
  - `command` с uvicorn и флагами `--proxy-headers --forwarded-allow-ips=172.16.0.0/12`,
    чтобы приложение видело реальный IP за прокси и лимитер работал по-людски;
  - `environment`: `DB_PATH=/app/storage/demo.sqlite3`, `COOKIE_SECURE=1`;
  - volumes: named volume `demo-data:/app/storage` (файл базы переживает пересборку),
    `./data/private/quest-answers.json:/app/data/private/quest-answers.json:ro`;
  - `restart: unless-stopped`;
  - healthcheck через python (в образе нет curl):
    `python -c "import urllib.request;urllib.request.urlopen('http://127.0.0.1:8000/health',timeout=3)"`.
- `caddy`: `caddy:2-alpine`, порты `80:80` и `443:443`, volume для `/data` и `/config`,
  монтирует `Caddyfile`, зависит от `api`.
- Секретов в файле нет: домен и email берутся из `.env`.

### 2. `Caddyfile`

- Один site-блок на домен из переменной окружения (`{$DOMAIN}`), email из `{$ACME_EMAIL}`.
- `reverse_proxy api:8000`.
- Сжатие `encode zstd gzip`.
- Таймауты запроса и заголовков.
- Не дублировать заголовки безопасности, которые уже отдаёт приложение
  (`X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`) — проверить
  в `backend/main.py` и не переопределять.

### 3. `.env.example`

```
# Скопируйте в .env и заполните. .env в .gitignore.
DOMAIN=example.com
ACME_EMAIL=you@example.com
```
Плюс одна строка комментария, что `.env` не коммитится.

### 4. `docs/DEPLOY.md`

Коротко и по шагам, для человека без опыта:

1. Что нужно: VPS с Docker, домен, A-запись на IP сервера.
2. Установка Docker на Ubuntu (официальный скрипт, одна команда).
3. Клонирование репозитория, создание `.env` из примера.
4. **Копирование `data/private/quest-answers.json` на сервер** — отдельным шагом,
   с предупреждением: без него квесты отдают 503, в git и в образе файла нет.
5. `docker compose -f docker-compose.prod.yml up -d --build`.
6. Проверки: `https://DOMAIN/health` → `{"status":"ok"}`; `/api/v1/places` → 200;
   `/api/v1/quest` → 200; сертификат валиден; главная открывается.
7. База: файл лежит в named volume, при пересборке не теряется; как сделать бэкап
   (скопировать `demo.sqlite3` из контейнера) и как откатиться на предыдущий образ.
8. Что делать при 429 (лимит), при 503 (нет ключей квестов), при невыданном сертификате
   (проверить A-запись и порт 80).
9. Отдельным блоком: у стенда **демо-вход**, пароли не восстановить, реальные пароли
   не использовать; в рейтинге виден логин.

### 5. Проверки, которые нужно реально выполнить и приложить вывод

- `docker compose -f docker-compose.prod.yml config` — конфиг валиден.
- Валидация Caddy:
  `docker run --rm -e DOMAIN=localhost -e ACME_EMAIL=a@b.c -v "$PWD/Caddyfile":/etc/caddy/Caddyfile caddy:2-alpine caddy validate --config /etc/caddy/Caddyfile`
- Проверка, что локальный запуск не сломан:
  `docker compose up -d --build` поднимает api на `127.0.0.1:8000`, `/health` отвечает 200.
- Если в репозитории уже есть база из параллельной ветки — убедиться, что
  `DB_PATH` и volume не конфликтуют с локальным запуском.

## Ограничения

- Никаких паролей, ключей, токенов, реальных доменов и IP в репозитории.
- Никаких изменений Python-кода, данных и фронтенда.
- Не публиковать и не деплоить от имени владельца.
- Если для решения нужно менять код приложения — стоп, вопрос в отчёте.

## Критерий приёмки

- `docker-compose.prod.yml` и `Caddyfile` валидны по командам выше.
- Локальный `docker compose up` не сломан.
- `docs/DEPLOY.md` позволяет поднять стенд по шагам, включая перенос файла ответов.
- В диффе только разрешённые файлы.

## Отчёт

Ветка, коммиты, что сделано, вывод команд проверки, отклонения, и отдельный список:
что владелец должен сделать руками (VPS, домен, A-запись, файл ответов).
