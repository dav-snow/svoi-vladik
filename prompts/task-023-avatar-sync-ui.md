# Задача 023: подключить аватары к серверной синхронизации

Фронтовая задача. Бэкенд уже готов (коммит `67b1828`), менять его не нужно.
Делать **после** редизайна GPT, чтобы не конфликтовать по
`frontend-design/dist/app.js`.

## Что уже есть на сервере

- `GET /api/v1/me/avatars` → `{ "selected", "unlocked", "completed_quest_ids" }`
  (401 для гостя).
- `PUT /api/v1/me/avatars` → `{ "selected": id | null }`; неизвестный id — 422,
  закрытый аватар — 409 `AVATAR_LOCKED`.
- `POST /api/v1/me/quests/import` → `{ "quest_ids": [...] }` (до 20) — разовая
  миграция локально завершённых квестов.
- `POST /api/v1/quest/{id}/complete` для вошедшего пользователя сам записывает
  уникальное завершение (если БД доступна).

Уровень открытия = `min(3, число уникальных завершённых квестов)`:
`compass` — 1, `crab` — 2, `bridge` — 3; `lighthouse`/`boat`/`sun` — 0.

## Что сделать в клиенте

Сейчас `avatarState` и `progress.quests` живут только в `localStorage`
(ключи `svoi-vladik-avatars-v1:<identity>` и `svoi-vladik-progress-v1`).
Нужно добавить серверный режим, сохранив гостевой.

1. **Сессия.** Когда `auth.user` известен (после `refreshMe`/входа), запросить
   `GET /me/avatars`. При 401/404/сети — остаться в локальном режиме, ничего
   не блокировать.
2. **Первый вход.** Собрать локально завершённые ID из `progress.quests`
   (`completed === true`), отправить в `POST /me/quests/import` (без дублей,
   не больше 20). Сервер вернёт актуальный `unlocked`; взять
   `max(локальный, серверный)`.
3. **Выбор.** Клик по доступному аватару: оптимистично обновить UI и
   `PUT /me/avatars`; при 401/409/сети — откатить выбор и показать `notify`.
   Гостю PUT не отправлять.
4. **Завершение квеста.** После успешного `/quest/{id}/complete` обновить
   `GET /me/avatars`, чтобы подтянуть разблокировку (локальный fallback
   остаётся). Не показывать награду повторно.
5. **Выход из аккаунта.** Вернуться к гостевому локальному состоянию, не
   теряя гостевые данные; не показывать чужие аватары.
6. **Приватность.** Не отправлять координаты, имя из обучения и личный
   маршрут. Только `quest_ids` и `selected`.
7. **Кэш.** Серверное состояние кэшировать в тот же локальный ключ по
   идентичности, чтобы офлайн-открытие профиля работало.

## Тесты

Добавить в `frontend-design/tests/avatar.test.mjs` (или новый файл) с
синтетическим `fetch`:

- гость не делает запросов к `/me/avatars`;
- вход импортирует завершённые квесты один раз и берёт `max` уровней;
- выбор аватара шлёт PUT и сохраняет его после ответа;
- 409/401 откатывают выбор и не ломают UI;
- завершение квеста обновляет уровень;
- выход возвращает гостевой выбор;
- в запросах нет координат/маршрута.
