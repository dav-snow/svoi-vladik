# Задача 001: контракт /api/v1 и единый формат ошибок

## Контекст

Проект «Свой Владик», бэкенд на FastAPI: `backend/main.py`, данные в `data/`, контейнер через `Dockerfile` и `docker-compose.yml`. Контракт — `docs/API.md`, документация для фронтенда — `INTEGRATION.md`.

В репозитории уже есть статический дизайн-прототип `frontend-design/` (MapLibre, свой `dist/`, локальные GeoJSON). Он **не обращается к API** и от твоих изменений не зависит. Раздел `prototypes/leninsky-map` — старый технический прототип, он сейчас монтируется в корень приложения; перенастраивать его не нужно.

Сейчас сервер отдаёт ручки по `/api/...`, хотя контракт требует префикс `/api/v1`. Ошибки приходят в двух разных форматах: для известных ручек `{"error": {"code": "404", ...}}`, для неизвестного пути — стандартный `{"detail": "Not Found"}` от Starlette. `INTEGRATION.md` описывает старый префикс и старые коды ошибок, то есть противоречит контракту.

Задача: привести пути и ошибки к контракту, добавить автоматические тесты. Функциональность не расширять.

## Разрешённые пути

- `backend/main.py`
- `backend/requirements-dev.txt` (создать при необходимости)
- `backend/tests/` (создать)
- `INTEGRATION.md`
- `Dockerfile`, `docker-compose.yml` — только если нужно для запуска тестов
- `README.md` — только короткий раздел «Запуск и проверки», если его ещё нет

Запрещено менять: `data/**`, `prototypes/**`, `frontend-design/**`, `docs/**`, `.github/**`, `scripts/**`, `prompts/**`.

## Что требуется

1. **Префикс `/api/v1`.** Все ручки API переезжают под `/api/v1`: места, карточка места, прогулки, квест, тестовые ручки. `GET /health` остаётся в корне — на него опирается деплой. Старые пути `/api/*` не сохранять: к API ещё не подключён ни один клиент, двойные пути создадут путаницу.
2. **Переименовать ручку прогулок** в `/api/v1/walks` по контракту. Внутренние модели (`Route`) переименовывать не обязательно, если это усложняет дифф, — но путь и ответ должны соответствовать `docs/API.md`.
3. **Единый формат ошибок.** Любая ошибка API — `{"error": {"code": "<SYMBOLIC_CODE>", "message": "<русский текст>"}}`:
   - `NOT_FOUND` — неизвестный ресурс и любой неизвестный путь под `/api/v1`;
   - `VALIDATION_ERROR` — неверный формат или значение параметра;
   - `METHOD_NOT_ALLOWED` — известный путь, неверный метод;
   - `INTERNAL_ERROR` — непойманное исключение, без трассировки в ответе.
   Код `INTERNAL_ERROR` не должен раскрывать текст исключения клиенту.
4. **Валидация ID.** `place_id` из пути проверять по шаблону `^[A-Za-z0-9_-]{1,64}$`. Несоответствие — 422 `VALIDATION_ERROR` (а не 404). Существующий ID по-прежнему отдаёт запись, неизвестный корректный ID — 404 `NOT_FOUND`.
5. **Тесты.** `pytest` + `httpx` (TestClient), отдельный `backend/requirements-dev.txt`, чтобы прод-образ не утяжелялся. Минимум проверок:
   - `/health` → 200 `{"status": "ok"}`;
   - `/api/v1/places` → 200, форма `{"items": [...], "total": N}`;
   - `/api/v1/places/{существующий id}` → 200;
   - `/api/v1/places/{несуществующий id}` → 404, формат `NOT_FOUND`;
   - `/api/v1/places/{id не по шаблону}` → 422 `VALIDATION_ERROR`;
   - неизвестный путь `/api/v1/nope` → 404 в **том же** едином формате;
   - неверный метод на существующем пути → 405 `METHOD_NOT_ALLOWED`;
   - старый путь `/api/places` → 404 (проверка, что переезд полный).
   Тесты не должны зависеть от сети и от времени запуска.
6. **Документация.** Обновить `INTEGRATION.md`: новые пути, новые коды ошибок, таблица кодов. Убрать утверждения, которые перестали быть верными. `docs/API.md` не трогать — он источник правды.
7. **Одна команда проверки.** Тесты должны запускаться одной документированной командой в контейнере или в окружении с зависимостями. Команду указать в отчёте и в `README.md`, если добавляешь раздел.

## Правила диффа (важно)

- Дифф минимальный: меняй только те строки, которые требует задача. Не переформатируй файл целиком, не переставляй импорты «по стандарту», не добавляй типизацию и docstring в нетронутые функции.
- Не переименовывай существующие модели, переменные и файлы без необходимости. Лучше оставить `Route` как есть, чем устраивать миграцию на `Walk`.
- Не рефактори «заодно». Увидел проблему — запиши в «Отклонения / вопросы», но не чини.
- Не удаляй существующие комментарии и пояснения, даже если кажутся лишними.
- Если после правки дифф больше ~200 строк — остановись и объясни, почему.

## Ограничения

- Не добавлять рантайм-зависимости. `pytest`/`httpx` — только dev.
- Не менять CORS, лимиты, работу с данными, поведение загрузки моков.
- Не трогать `frontend-design/**` и `prototypes/**` — это чужая зона.
- Не переписывать `backend/main.py` с нуля: правки точечные, существующие обработчики и fallback сохраняются.
- Не публиковать в ответах секреты и трассировки.
- Не коммитить папку `prompts/` и файл `AGENTS.md`.
- Если считаешь, что что-то в ТЗ противоречит контракту, — не решай молча, вынеси в раздел «Отклонения».

## Критерий приёмки

- `docker build` проходит, контейнер стартует, `/health` отвечает.
- `GET /openapi.json` содержит только пути с префиксом `/api/v1` (плюс `/health`), старых `/api/*` нет.
- Все перечисленные проверки проходят, тесты падают при откате любого исправления (убедись хотя бы на одном пункте).
- `INTEGRATION.md` соответствует реальному поведению: пути, коды, примеры.
- В диффе нет файлов вне разрешённого списка.
