# ЧАСТЬ 2. Точки не должны пропадать (второй коммит)

## Проблема

После нажатия «Что рядом со мной» включается фильтр по радиусу: список и маркеры за пределами радиуса исчезают. Вернуть полный каталог можно только через «Не использовать моё местоположение» — мелкая ссылка под статусом, её не находят. Пользователь остаётся с одной-двумя точками и не понимает, как вернуть остальные.

## Что сделать (фронтенд)

1. В объект `geo` добавить флаг `radiusFilter: true` (по умолчанию фильтр включён — так требует `docs/GEOLOCATION.md`).
2. В `renderPlaces()` при наличии позиции:
   - если `geo.radiusFilter === true` — фильтровать по `distanceM <= radiusM`, как сейчас;
   - если `false` — не фильтровать, но расстояния считать и сортировать по возрастанию (устойчивый тай-брейк по `id` сохранить).
3. В блоке `nearby-actions` добавить кнопку `id="nearby-show-all"`:
   - когда фильтр включён — текст «Показать все места»;
   - когда выключен — текст «Только рядом»;
   - переключение `geo.radiusFilter` и `renderPlaces()`, без нового запроса геолокации.
4. Статус (`#nearby-status`) при активной позиции дополнить счётчиком: «Рядом со мной · 1 км · показано 2 из 3 мест». При выключенном фильтре — «3 из 3». Точность и время определения сохранить.
5. `nearby-actions` показывать всегда, когда позиция получена (`geo.origin === "device"`), а не только при ошибках.
6. Очистка позиции (`clearNearby`) возвращает `geo.radiusFilter = true`.
7. Переключение радиуса в селекте не включает фильтр принудительно, но обновляет счётчик; если фильтр был выключен — он остаётся выключенным.
8. Маркеры мест скрывать только те, что не попали в текущую выдачу (как сейчас). При «Показать все места» все маркеры возвращаются.

## Критерий приёмки части 2 (фронт)

- `node --check frontend-design/dist/app.js`.
- После получения позиции: видно N из M, кнопка «Показать все места» возвращает весь каталог с расстояниями и сортировкой от ближнего, «Только рядом» снова включает радиус.
- «Не использовать моё местоположение» очищает позицию, маркер и возвращает обычный каталог без расстояний.
- Смена радиуса/категории/поиска не вызывает нового запроса геолокации.

# ЧАСТЬ 3. Дорога для новых точек (второй коммит, бэкенд)

## Проблема

Данных две копии: `data/geo/leninsky-poi-candidates.geojson` (источник, на него ссылаются документы) и `frontend-design/dist/data/leninsky-poi-candidates.geojson` (то, что реально раздаётся). Сейчас они побайтово одинаковые, но стоит добавить точки в одну — вторая отстанет, и на экране ничего не изменится. Плюс `app.js:210` фильтрует точки по `META[f.id]`, поэтому новые точки не отрисуются, даже если попадут в файл.

## Что сделать

1. **Один источник правды — `data/geo/`.** В `backend/main.py` добавить ДО монтирования `/data` два явных маршрута:
   - `GET /data/leninsky-boundary.geojson`;
   - `GET /data/leninsky-poi-candidates.geojson`.
   Оба читают файл из `data/geo/` и отдают через `FileResponse` с `application/geo+json`. Остальное из `/data` (`map-style.json` и прочее, если появится) продолжает отдаваться из `frontend-design/dist/data` через существующий mount. Маршруты должны стоять раньше mount, иначе перехватит он.
2. Тест: оба пути отдают 200, `json.loads` проходит, `"type": "FeatureCollection"`, и содержимое совпадает с `data/geo/...` (например, по числу `features`). Плюс тест, что `/data/map-style.json` всё ещё отдаётся из фронтовой папки, если он там есть; если нет — не добавляй.
3. `INTEGRATION.md`: описать, что `/data/leninsky-*.geojson` — это файлы из `data/geo/` (единственный источник правды), а остальные файлы фронта — из `frontend-design/dist/data`. Указать: новые места добавляются только в `data/geo/leninsky-poi-candidates.geojson`.
4. **Фронтенд:** снять жёсткий фильтр по `META` в `preparePlaces`. Теперь любая точка из GeoJSON отображается, а `META` — необязательный оверрайд:
   - `title`: `m?.short || properties.name || "Место без названия"`;
   - `label`: `m?.label || title`;
   - `kind`: `m?.kind || properties.category || "Ленинский район"`;
   - `description`: `m?.description || "Точка из каталога Ленинского района. Условия посещения проверьте по источнику."`;
   - `image`: `m?.image || "guide.svg"` (заглушка из существующих ассетов, `assets/undefined` быть не должно);
   - координаты и `category` — из `properties`, как сейчас.
   Существующие три записи `META` не менять: их тексты — редакторские.
5. `README.md`: одна строка о том, что новые места добавляются в `data/geo/leninsky-poi-candidates.geojson`, и что `frontend-design/dist/data` для этих двух файлов больше не источник.

## Критерий приёмки части 3

- `curl /data/leninsky-boundary.geojson` → 200, `application/geo+json`, содержимое = `data/geo/...`.
- `curl /data/leninsky-poi-candidates.geojson` → 200, то же.
- Временная проверка (сделать и убрать, в коммит не включать): добавить в `data/geo/leninsky-poi-candidates.geojson` тестовую точку с новым `id` и валидными координатами, поднять контейнер, убедиться, что она появляется в списке/на карте с названием из `properties.name` и без ошибок в консоли. Потом откатить `git checkout -- data/geo/leninsky-poi-candidates.geojson`. В отчёте указать, что проверка проведена и откачена.
- `pytest` зелёный, `node --check` проходит.
