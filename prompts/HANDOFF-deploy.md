# Передача: деплой демо на сервер

Ты получаешь доступ к серверу и пакет файлов. Задача — поднять демо на
`https://176-53-253-60.sslip.io` и проверить, что всё живое. В репозиторий ничего
не пушить, `main` не трогать, пароли и ключи в файлы не вписывать.

## Что тебе передали

1. `scripts/server-setup.sh` — одноразовая подготовка сервера.
2. `scripts/deploy-remote.sh` — сам деплой, запускается с твоей машины.
3. `deploy.cmd` — то же для Windows в один двойной клик (необязательно).
4. `data/private/quest-answers.json` — серверные ключи ответов квестов.
   **Отдельным закрытым каналом, не в Git.** Без него квесты отдают 503.
5. В репозитории, ветка `main` после мержа задачи 011, должны появиться:
   `docker-compose.prod.yml`, `Caddyfile`, `.env.example`, `docs/DEPLOY.md`.
   Если их нет — стоп, ждём мерж, скрипт сам об этом скажет.

## Доступ

- хост: `176.53.253.60`, порт 22, пользователь `tech`, sudo через `sudo -i`;
- вход только по SSH-ключу, пароль отключён; ключ у тебя;
- DNS: домена нет, используем `176-53-253-60.sslip.io` — это имя резолвится
  в тот же IP, Let's Encrypt выдаст на него настоящий сертификат.

## Порядок

### 1. Проверить доступ

```
ssh tech@176.53.253.60 true
```

Молча — хорошо. `Permission denied` — ключ не тот или не добавлен.

### 2. Подготовить сервер (один раз)

Скопировать скрипт и запустить, введя пароль sudo:

```
scp scripts/server-setup.sh tech@176.53.253.60:~
ssh tech@176.53.253.60 'bash ~/server-setup.sh tech'
```

Скрипт ставит Docker и compose-плагин, добавляет `tech` в группу `docker`,
создаёт `/opt/svoi-vladik`.

**После этого выйти и зайти снова** (группа применяется при новом логине),
и проверить:

```
ssh tech@176.53.253.60 'docker ps'
```

Должен напечатать шапку таблицы без sudo. Если «permission denied» — группа
не применилась, перезайди.

### 3. Проверить файрвол

Caddy сначала проверяет домен по 80, потом работает по 443. Если в панели
хостинга есть файрвол — открыть 80 и 443. Проверка снаружи:

```
curl -I http://176-53-253-60.sslip.io
```

### 4. Положить файл ответов

Он должен лежать рядом с репозиторием на твоей машине:
`data/private/quest-answers.json`. Скрипт деплоя копирует его на сервер сам,
если файл есть локально. Нет файла — скрипт остановится и скажет об этом.

### 5. Запустить деплой

Из корня репозитория:

```
bash scripts/deploy-remote.sh tech 176.53.253.60 176-53-253-60.sslip.io
```

Или двойной клик по `deploy.cmd` (там дефолтный домен уже прописан, можно нажать Enter).

Что скрипт делает: проверяет SSH и Docker, копирует проект в `/opt/svoi-vladik`
(rsync, без `.git`), создаёт `.env` с доменом (права 600), собирает и поднимает
прод-compose, ждёт HTTPS до двух минут, гоняет смоук.

## Что считать успехом

```
curl -fsS https://176-53-253-60.sslip.io/health
```
→ `{"status":"ok"}`

```
curl -s -o /dev/null -w '%{http_code}\n' https://176-53-253-60.sslip.io/api/v1/places
```
→ `200`

```
curl -s -X POST https://176-53-253-60.sslip.io/api/v1/quest/quest-three-keys/answer \
  -H 'Content-Type: application/json' \
  -d '{"stop_id":"keys-house","option_id":"a"}'
```
→ `{"correct":true,...}`. Если `503` — не подложился файл ответов.

Плюс открыть в браузере `https://176-53-253-60.sslip.io/` с телефона:
карта, список, кнопка «Что рядом со мной» (спросит разрешение — это нормально
на HTTPS), прогулки, квест.

## Если не получилось

- **Сертификат не выдаётся**: проверь `nslookup 176-53-253-60.sslip.io` — должен
  вернуть `176.53.253.60`; проверь, открыт ли 80; логи:
  `ssh tech@176.53.253.60 'cd /opt/svoi-vladik && docker compose -f docker-compose.prod.yml logs caddy --tail=80'`.
- **429 при быстрых нажатиях**: сработал лимит, это нормально, подожди минуту.
- **503 на проверке ответа**: нет `data/private/quest-answers.json` на сервере.
- **Белый экран**: логи `docker compose -f docker-compose.prod.yml logs api --tail=80`.

## Что нельзя

- Пушить в `main` и менять код приложения.
- Класть пароли, ключи и `.env` в репозиторий.
- Открывать наружу порт 8000: приложение должно быть доступно только через Caddy.
- Оставлять `data/private/quest-answers.json` в публичной папке или отдавать его по ссылке.

## Что прислать обратно

1. URL стенда и вывод `/health`.
2. Код ответа `/api/v1/places` и `/api/v1/quest`.
3. Результат проверки ответа на квест (200 или 503).
4. Скриншот главной с телефона и с ноутбука.
5. Всё, что пришлось чинить руками.
