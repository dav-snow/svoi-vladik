# Задача 012: база, вход, посещения, лайки, профиль и рейтинг

## Что делаем

MVP-авторизация и социальный слой демо:

- вход по логину и паролю (без email, 2FA и восстановления) — осознанная рамка демо;
- **посещение**: пользователь отмечает, что был в месте; отметка пишется в его профиль;
- **лайк**: пользователь отмечает, что место понравилось;
- у места **два независимых счётчика**: сколько посетило и скольким понравилось;
- **профиль**: свой логин, сколько посетил, сколько лайкнул, списки ID мест;
- **рейтинг игроков по посещениям**: кто больше отметил, тот выше; лайки в рейтинге
  показываются, но на место в топе не влияют.

Не делаем: email, сброс пароля, 2FA, роли, модерацию, удаление аккаунта, аватарки,
бейджи, уровни, показ чужих полных профилей, соревновательные награды.

## Незыблемые три правила

1. Пароль хранится **только** как хэш `hashlib.scrypt` с солью; в открытом виде — нигде.
2. Сессия — серверный токен в `HttpOnly` куке. Не `localStorage`, не токен в JS.
3. Вход ограничен по частоте на IP и на логин; перебор за минуту невозможен.

## Стек

SQLite через стандартный `sqlite3`. Никаких новых зависимостей, `SQLAlchemy`,
`passlib`, `jose`, `bcrypt`-пакетов. Один процесс, WAL, `busy_timeout`,
подключение на запрос, только параметризованные запросы.

`DB_PATH` из env, по умолчанию `data/demo.sqlite3`; файл в `.gitignore`.
База недоступна или битая — API не падает: счётчики 0, POST-ручки 503.

## Схема

```sql
users(id TEXT PRIMARY KEY, login TEXT UNIQUE NOT NULL, password_hash TEXT NOT NULL,
      created_at TEXT NOT NULL)
sessions(token_hash TEXT PRIMARY KEY, user_id TEXT NOT NULL,
         created_at TEXT NOT NULL, expires_at TEXT NOT NULL)
visits(user_id TEXT NOT NULL, place_id TEXT NOT NULL, created_at TEXT NOT NULL,
       PRIMARY KEY(user_id, place_id))
likes(user_id TEXT NOT NULL, place_id TEXT NOT NULL, created_at TEXT NOT NULL,
      PRIMARY KEY(user_id, place_id))
```

- `id` и `user_id` — `secrets.token_hex(16)`.
- `token_hash` — sha256 от токена сессии; сырой токен в базе не хранится.
- `visits` и `likes` — независимые таблицы: лайк не означает посещение и наоборот.
- Одинаковые отметки невозможны: пара `(user_id, place_id)` уникальна.
- Все таблицы создаются идемпотентно (`CREATE TABLE IF NOT EXISTS`) при старте.

## Пароли

- Формат: `scrypt$<n>$<r>$<p>$<salt_hex>$<hash_hex>`, `n=2**14, r=8, p=1`, dklen 32,
  соль 16 байт.
- Сравнение — `hmac.compare_digest`.
- Логин 3–32 символа `[A-Za-z0-9_.-]`, пароль 8–128 символов.
- Пароль не появляется в ответах, логах и трейсах никогда.

## Сессии

- Токен `secrets.token_urlsafe(32)`, в базе только его sha256.
- Кука `sv_session`: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Max-Age` 7 дней.
- `Secure` включается переменной `COOKIE_SECURE=1` (на HTTPS обязательно).
- Просроченная сессия недействительна. Выход удаляет строку и сбрасывает куку.

## Ручки

### Авторизация

| Метод | Путь | Поведение |
|---|---|---|
| POST | `/api/v1/auth/register` | `{login,password}` → 201, кука, `{"user":{"id","login"}}`; занятый логин → 409 |
| POST | `/api/v1/auth/login` | `{login,password}` → 200, кука; неверная пара → 401 без подсказки, что именно неверно |
| POST | `/api/v1/auth/logout` | 204, кука сбрасывается |
| GET | `/api/v1/me` | 200 `{"user":{"id","login"}}` либо 401 |

### Посещения и лайки

| Метод | Путь | Поведение |
|---|---|---|
| POST | `/api/v1/places/{place_id}/visit` | 200 `{"visited":true,"visits":N}`; идемпотентно; без сессии 401; неизвестное место 404 |
| DELETE | `/api/v1/places/{place_id}/visit` | 200 `{"visited":false,"visits":N}`; идемпотентно |
| POST | `/api/v1/places/{place_id}/like` | 200 `{"liked":true,"likes":N}`; идемпотентно; без сессии 401; неизвестное место 404 |
| DELETE | `/api/v1/places/{place_id}/like` | 200 `{"liked":false,"likes":N}`; идемпотентно |

### Профиль и рейтинг

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/v1/me/profile` | `{"user":{"id","login"},"stats":{"visits":N,"likes":M},"visited_place_ids":[...],"liked_place_ids":[...]}`; без сессии 401 |
| GET | `/api/v1/leaderboard?limit=10` | `{"items":[{"login":"kostya","visits":7,"likes":3}],"total":2}` |

Правила рейтинга:

- попадают только пользователи хотя бы с одним посещением;
- сортировка строго по `visits` по убыванию, при равенстве — по `login` по возрастанию;
- `likes` отдаются для показа, но место в топе не меняют;
- `limit` 1–20, по умолчанию 10; `limit` вне диапазона, повтор или лишний параметр → 422;
- в ответе только `login`, `visits`, `likes`: никаких id, почты, дат регистрации
  и списков мест. Списки мест — только в своём профиле.

### Поля мест

`GET /api/v1/places` и карточка места получают четыре вычисляемых поля:
`visits: int`, `likes: int`, `visited_by_me: bool`, `liked_by_me: bool`
(для анонимных запросов оба `false`). В JSON-файлы эти поля не пишутся.

## Лимиты

- Регистрация и вход: не больше 10 попыток в минуту на IP и отдельно на логин.
  Превышение → 429 с `Retry-After: 60`.
- Посещения и лайки: существующий `POST_LIMITER` (30 в минуту), применяется и к
  DELETE, чтобы снятие/постановка не превращались в бесплатный цикл.
- Лимит тела 16 КиБ действует как сейчас.

## Тесты

`backend/tests/test_auth.py`:

- регистрация → 201, кука `HttpOnly` и `SameSite=Lax`, `/me` → 200;
- повторная регистрация того же логина → 409;
- верный пароль → 200, неверный → 401, сообщения не различают «нет логина» и «неверный пароль»;
- в базе `password_hash` начинается с `scrypt$` и не содержит исходного пароля;
- `sessions.token_hash` не равен токену из куки;
- logout → 204, затем `/me` → 401;
- 11 неудачных попыток входа подряд → 429.

`backend/tests/test_visits.py`:

- без сессии `POST /visit` → 401;
- первая отметка → `visits:1`, повтор тем же пользователем → `visits:1`;
- второй пользователь → `visits:2`, `visited_by_me:true` только у него;
- `DELETE /visit` уменьшает счётчик, повторный delete не ломается;
- неизвестный `place_id` → 404;
- в таблице `visits` нет IP, координат и логинов — только `user_id`, `place_id`, `created_at`.

`backend/tests/test_likes.py`:

- лайк не связан с посещением: можно лайкнуть без отметки;
- первый лайк → `likes:1`, повтор → `likes:1`;
- `DELETE /like` → `likes:0`, повторный delete не ломается;
- `visits` и `likes` считаются независимо и не влияют друг на друга.

`backend/tests/test_profile_leaderboard.py`:

- `/me/profile`: правильные `stats`, списки ID соответствуют поставленным отметкам;
- чужой профиль недоступен (ручки нет) — но проверить, что `/me/profile` без сессии 401;
- рейтинг: пользователь с 3 посещениями выше пользователя с 1;
- при равных посещениях сортировка по логину;
- пользователь без посещений в рейтинг не попадает;
- `limit=1` работает, `limit=0` и `limit=21` → 422, лишний параметр → 422;
- в ответе нет полей кроме `login`, `visits`, `likes`.

Общее: все тесты на временном `DB_PATH` через `monkeypatch`; реальная база не трогается.
Битый `DB_PATH` → места отдаются с нулями, POST → 503, сервер жив.

## Ограничения

- Никаких новых зависимостей и никаких ORM.
- Не менять квесты, гиды, прогулки и существующий лимитер по существу.
- Не логировать тела запросов, пароли, куки, IP.
- Пароли и токены не появляются в ответах API.
- Если для реализации нужно нарушить рамки (внешняя библиотека, изменение контракта
  существующих ручек) — стоп, вопрос в отчёте, а не самовольное решение.

## Критерий приёмки

- `pytest` зелёный, старые тесты не сломаны.
- Вручную curl: регистрация → кука → `/me` → `/me/profile` → `POST /visit` →
  `POST /like` → счётчики у места → повтор не растит → `/leaderboard` показывает
  логин с числом → `DELETE /like` → logout → `/me` 401.
- `docker compose up -d --build` работает; файл базы создаётся и не попадает в git.
- В базе нет открытых паролей и сырых токенов сессий, нет IP и координат.
