# Задача 002: один origin — новый фронт и API под /api/v1

## Контекст

Проект «Свой Владик», бэкенд на FastAPI: `backend/main.py`. Дизайн-прототип: `frontend-design/dist/` (buildless, MapLibre, свои локальные GeoJSON в `dist/data/`). Контракт — `docs/API.md`, документация для фронта — `INTEGRATION.md`.

Что не так сейчас:

- API живёт по `/api/...`, контракт требует `/api/v1`.
- Ошибки в двух форматах: известные ручки отдают `{"error": {"code": "404", ...}}`, неизвестный путь — `{"detail": "Not Found"}` от Starlette.
- Корень приложения раздаёт устаревший `prototypes/leninsky-map`, а не новый дизайн.
- `Dockerfile` не копирует `frontend-design`, поэтому в контейнере нового фронта нет вообще.
- Тестов нет.

Ранее отдельной задачей 001 планировался только переезд на `/api/v1`; она не выполнялась. **Эта задача включает её целиком** — не дублируй, делай сразу обе части.

Задача: один контейнер отдаёт новый фронт и API с одного адреса, пути и ошибки соответствуют контракту, поведение покрыто тестами.

## Разрешённые пути

- `backend/main.py`
- `backend/requirements-dev.txt` (создать)
- `backend/tests/` (создать)
- `Dockerfile`
- `docker-compose.yml` — только если нужно для проверки
- `INTEGRATION.md`
- `README.md` — только раздел «Запуск и проверки», если его нет

Запрещено менять: `data/**`, `prototypes/**` (не удалять и не переносить), `frontend-design/**`, `docs/**`, `.github/**`, `scripts/**`, `prompts/**`, `AGENTS.md`.

## Что требуется

### A. API под `/api/v1`

1. Все API-ручки переезжают под `/api/v1`: места, карточка места, прогулки, квест, тестовые ручки. `GET /health` остаётся в корне. Старые `/api/*` не сохранять как алиасы — клиентов у API пока нет.
2. Ручка прогулок — `/api/v1/walks` (по контракту), ответ в форме `{"items": [...], "total": N}`.
3. Единый формат ошибок: `{"error": {"code": "<SYMBOLIC_CODE>", "message": "<русский текст>"}}` для **всех** путей, включая неизвестные:
   - `NOT_FOUND` — неизвестный ресурс и неизвестный путь под `/api/v1`;
   - `VALIDATION_ERROR` — неверный формат/значение параметра;
   - `METHOD_NOT_ALLOWED` — известный путь, неверный метод;
   - `INTERNAL_ERROR` — непойманное исключение, без трассировки и текста исключения в ответе.
4. `place_id` из пути проверять по `^[A-Za-z0-9_-]{1,64}$`: несоответствие — 422 `VALIDATION_ERROR`, корректный неизвестный — 404 `NOT_FOUND`.

### B. Корень отдаёт новый фронт

5. `frontend-design/dist` монтируется в `/` (`html=True`), монтируется последним, чтобы не перехватывать `/api/*`, `/health`, `/docs`.
6. Старый `prototypes/leninsky-map` больше не монтируется в `/`. Файлы не удалять, историю не переписывать.
7. `GET /data/...` продолжает работать.

### C. Контейнер

8. `Dockerfile` копирует `frontend-design/dist` в образ, чтобы контейнер отдавал новый фронт.
9. `docker build` + `docker run -p 8000:8000` — корень отдаёт HTML нового дизайна, API отвечает.

### D. Тесты

10. `pytest` + `httpx` (`TestClient`), зависимости в `backend/requirements-dev.txt` (прод-образ ими не утяжелять). Проверки:
    - `/health` → 200 `{"status": "ok"}`;
    - `/` → 200 и HTML нового дизайна (проверить устойчивый маркер из `frontend-design/dist/index.html`, например `<title>` или подключение `maplibre`);
    - `/api/v1/places` → 200, форма `{"items": [...], "total": N}`;
    - `/api/v1/places/{существующий id}` → 200;
    - `/api/v1/places/{несуществующий id}` → 404 `NOT_FOUND`;
    - `/api/v1/places/{id не по шаблону}` → 422 `VALIDATION_ERROR`;
    - `/api/v1/nope` → 404 в том же едином формате;
    - неверный метод на существующем пути → 405 `METHOD_NOT_ALLOWED`;
    - `/api/places` → 404 (переезд полный);
    - `/data/geo/leninsky-boundary.geojson` → 200.
11. Тесты не зависят от сети и от времени запуска. Карта в контейнере без интернета не грузится — это нормально, проверяем только отдачу HTML и данных.

### E. Документация

12. `INTEGRATION.md`: новые пути, коды ошибок с таблицей, что отдаётся на `/`, команда запуска тестов. Убрать устаревшие утверждения.
13. `docs/API.md` не трогать — источник правды.
14. В `README.md` добавить/обновить раздел запуска: сборка, запуск, тесты.

## Правила диффа (важно)

- Дифф минимальный: только строки, которые требует задача. Не переформатировать файл целиком.
- Не переименовывать модели `Place`/`Route`/`Quest` и не переписывать `main.py` с нуля — правки точечные, существующие загрузчики, fallback на моки и обработчики сохраняются.
- Не рефакторить «заодно»: заметил проблему — в «Отклонения», не чини.
- Не удалять существующие комментарии и пояснения.
- Не трогать `frontend-design/**`: фронт к API **не подключаем** в этой задаче, `app.js` не правим, данные остаются локальными. Это следующая задача.
- Если дифф выходит больше ~350 строк — остановись и объясни, почему.

## Ограничения

- Не добавлять рантайм-зависимости. `pytest`/`httpx` — только dev.
- Не менять CORS, лимиты запросов и работу с данными.
- Не публиковать секреты и трассировки в ответах.
- Не коммитить `prompts/` и `AGENTS.md`.
- Если ТЗ противоречит контракту или коду — стоп, вопрос в «Отклонениях», а не самовольное решение.

## Критерий приёмки

- `docker build` проходит, контейнер стартует, `/health` отвечает.
- `GET /` отдаёт HTML нового дизайна (не старый прототип).
- `GET /openapi.json` содержит только `/api/v1/*` и `/health`, старых `/api/*` нет.
- Все тесты зелёные, запускаются одной документированной командой.
- `INTEGRATION.md` соответствует фактическому поведению.
- В диффе нет файлов вне разрешённого списка.

## Отчёт

По шаблону `prompts/PROTOCOL.md`: ветка и коммиты; что сделано по пунктам; файлы; точные команды проверки и их вывод; отклонения и вопросы; что не сделано и почему.
