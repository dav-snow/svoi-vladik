# Свой Владик

**Освоиться в городе, найти своё место и узнать его историю.**

Мобильное веб-приложение для первокурсников, новых жителей Владивостока и местной молодёжи. Объединяем темы вайбатона №13, №14 и №15 одним сценарием: человек выбирает интересы и бюджет, находит доступное пространство, получает подсказки новичку и знакомится с городом через короткий исторический квест.

**Статус: подготовительный этап.** Здесь пока документация и план команды. Приложение, сервер, реальные карточки мест и макеты ещё предстоит создать. Рабочее название и стек можно уточнить на старте.

Репозиторий: [dav-snow/svoi-vladik](https://github.com/dav-snow/svoi-vladik).

## Сценарий

«Я недавно приехал. У меня два часа, хочу бесплатно познакомиться с городом» → интересы и бюджет → список и карта подходящих мест → карточка с условиями и источником → внешняя навигация → связанный квест из трёх точек → история, задание и полезное место для продолжения дня.

## Первая версия

- 15 проверенных мест для учёбы, творчества, встреч и отдыха; фильтры по интересам и стоимости.
- До трёх подтверждённых бесплатных событий; если актуальных нет — честное пустое состояние.
- Краткие советы новичку и переход во внешнюю навигацию.
- Один текстовый исторический квест из трёх точек: персонаж, факты с источниками, задания и локальное сохранение прогресса.
- Мобильные экраны, список и карта; работа без обязательной геолокации и регистрации.

После основного сценария: избранное, аудио и подбор с ИИ из проверенной базы. Собственный транспортный планировщик и социальная сеть в первую версию не входят.

## Команда

| Роль | Главный результат |
|---|---|
| Дизайнер / UX/UI / редактор | Кликабельный прототип, компоненты, проверенные карточки и история квеста |
| Бэкендер / данные | API каталога и квеста, фильтрация, проверка данных; позже — ИИ-подбор |
| Фронтендер / интегратор | Мобильное приложение, подключение API, карта, квест, сборка и демо |

Третья роль предложена исходя из задачи; имена и GitHub-логины участников ещё не заданы. Полные задачи, порядок взаимодействия и пример плана на 48 часов — в [TEAM](docs/TEAM.md). 48 часов — пример, фактический срок не указан.

## Как начать работу

1. Всем прочитать концепцию и подтвердить MVP, срок и третью роль.
2. Указать владельцев задач в бэклоге; владелец репозитория добавляет двух участников по их GitHub-логинам.
3. Согласовать API и примеры данных. Дизайнер начинает прототип и сбор источников, фронтендер — экраны на моках, бэкендер — API.
4. Как можно раньше соединить один экран с реальным API, затем завершить весь сценарий и репетировать демо.

Скачать материалы можно командой:

```sh
git clone https://github.com/dav-snow/svoi-vladik.git
cd svoi-vladik
```

**Команд запуска приложения пока нет:** код ещё не создан. При реализации разработчики добавят зависимости, `.env.example` без секретов и проверенную инструкцию запуска фронтенда и бэкенда. Репозиторий пока без выбранной открытой лицензии; публичность сама по себе не задаёт условия повторного использования. Лицензию согласуем командой, права на внешние материалы учитываем отдельно.

## Роль ИИ

ИИ помогает создавать проект: уточнять сценарий, прототипировать, писать и проверять код, готовить тексты. Человек отвечает за принятый результат; история, цены, условия и расписания сверяются с источниками. ИИ внутри продукта — дополнительная функция, которая выбирает только существующие записи; основной сценарий работает без неё. Конкретные требования к ИИ команда сверяет с правилами вайбатона.
