# Свой Владик

**Актуальное решение команды:** добавляем выбор из шести готовых аватаров профиля. Маяк, кораблик и солнце доступны сразу; компас, краб и мост открываются за завершение одного, двух и трёх разных квестов. [Архив PNG и правила](docs/PROFILE_AVATARS.md). Это целевой сценарий для реализации. Одежда, шапки, скины, аксессуары, редактор персонажа и магазин остаются исключены. Общий маскот-проводница Влада остаётся отдельно от аватара пользователя. Предыдущие запреты на аватары в других документах следует читать с учётом этого нового решения.

Веб-приложение для новичка в Ленинском районе Владивостока: найти полезное место, выбрать прогулку и познакомиться с историей города через квест с персонажем-проводницей и итоговым опросом.

**География первой версии — только Ленинский район Владивостока.** Для ускорения разработки первые места, обе прогулки и исторический квест собираем на одном компактном участке внутри района. Полного покрытия района в демо не обещаем; другие районы остаются за пределами текущего объёма.

**Статус: рабочая локальная сборка.** Объединены адаптивный интерфейс, FastAPI, помощница с шестью состояниями, 14 активных мест-кандидатов, 4 прогулки и 4 квеста (два по 3 и два по 5 заданий). Подключены геолокация по кнопке, ручной старт, расстояния по прямой, сохранение прогресса. Предметная награда в прежней сборке была, но исключена из целевого продукта; её код этим обновлением документации не удалён. Каталог и переходы требуют редакторской и полевой проверки: это не заявление о 14 проверенных местах. План на **36 часов** ниже сохраняется как история принятого объёма, а не отчёт о содержательной приёмке.

Публичный репозиторий: [dav-snow/svoi-vladik](https://github.com/dav-snow/svoi-vladik).

**Запуск:** двойной щелчок по [start.cmd](start.cmd) либо `npm.cmd start`. Открывается **http://127.0.0.1:8000/**. Первичная подготовка Python — [RUN_LOCAL](docs/RUN_LOCAL.md). [Клиент](frontend-design/README.md), [реальный контракт API](INTEGRATION.md), [импорт и исключённые кандидаты](docs/CONTENT_IMPORT.md), [проверка сборки](docs/INTEGRATION_QA.md).

Серверный файл ответов хранится локально и исключён из публичного Git. На новом сервере нужна отдельная [конфигурация квестов](data/private/README.md); в текущем рабочем окружении она уже подготовлена.

## Расширенная подборка для команды

[Места, прогулки и квесты версии 2](docs/ROUTES_AND_QUESTS_V2.md): семь новых кандидатов, два квеста по пять точек и сценарий для компании. Это согласованный к публикации редакционный документ, но места и переходы ещё требуют проверки. Он не увеличивает обязательный объём P0: команда выбирает один квест и две прогулки.

## Что делаем за 36 часов

**Один сценарий:** «Я здесь впервые» → список и карта → проверенное место → готовая прогулка → исторический квест → экран завершения квеста.

- **8 проверенных мест** на одном компактном участке Ленинского района; 9–10 добавляем только при готовом основном пути и в том же районе. Цена и условия посещения подтверждены либо явно не уточнены.
- «Я тут впервые» → **«Что рядом со мной»**: по разрешению определяем позицию, показываем «Вы здесь» и ближайшие места каталога по расстоянию; интересы, бюджет и радиус уточняют выдачу. Координаты используются только в браузере, без истории перемещений. Без геолокации старт выбирается вручную. Расстояние приблизительное, по прямой, не время пути.
- **2 готовые прогулки по 3 точки**. Точки могут пересекаться. Переход во внешний навигатор; собственного построения пути нет. В демо честное название «Прогулка», без обещания заполнить весь день.
- **1 исторический квест на 3 точки**: факт с источником, художественная реплика, вопрос, пояснение и сохранение прогресса.
- Локальное сохранение прогресса и экран завершения квеста, без аккаунта и рейтинга.
- Статичный маскот с тремя кнопками «Поесть», «Туалет», «Досуг»: фильтр проверенного каталога и короткие памятки; при отсутствии данных — понятное сообщение.

**P1 после рабочего P0:** замена одной точки из подготовленных кандидатов, ИИ-подбор, избранное, аудио, до 3 подтверждённых событий. **После вайбатона:** отзывы, рейтинги, загрузка фото, ежедневные задания, друзья, чат, мультиплеер, общий лидерборд.

Если к контрольным точкам не успеваем, переходим к **6 местам и 1 прогулке**, сохраняя рабочий квест и честность данных. Режим сокращения описан в плане и не считается выполнением полного P0.

## Кто что делает

| Участник | Ответственность | Первый результат |
|---|---|---|
| **1 — дизайн + фронтенд** | Минимальный UI, карта/список, фильтры, прогулка, квест и локальный прогресс | До H6–8 один экран с реальным API |
| **2 — бэкенд** | Контракт, JSON API, импорт данных, проверки ввода, инфраструктура и техническая безопасность | До H4 API на согласованных примерах, до H8 ранний стенд |
| **3 — продукт + контент + ручная приёмка** | Источники, каталог, квест, пользовательские проверки, баги, защита и журнал ИИ | До H4 первые 3 карточки и черновик точки квеста |

H0 — согласованное время старта, не полночь. План включает отдых и сон; это не 36 часов непрерывной работы. Техническое ревью выполняют разработчики, содержательную приёмку ведёт третий участник.

## Начало работы

1. Вместе прочитать оценку и подтвердить объём P0; сверить правила вайбатона и фактический дедлайн.
2. Вписать логины и владельцев задач. Владелец добавляет двух участников в репозиторий; пароли не передаются.
3. За первые два часа согласовать API, примеры ответов и границы файлов. Дальше работать параллельно по плану.
4. Соединить первый экран с API до H6–8 и рано проверить размещение. К H27 прекратить добавление функций; оставшееся время — исправления, приёмка и защита.

```sh
git clone https://github.com/dav-snow/svoi-vladik.git
cd svoi-vladik
```

## Запуск и проверки

Один контейнер отдаёт API и новый фронт с одного адреса `http://localhost:8000`:
бэкенд по `/api/v1/*` и `/health`, дизайн-прототип `frontend-design/dist/` по `/`,
исходные GeoJSON по `/data/...`. Подробный контракт — в [`INTEGRATION.md`](INTEGRATION.md),
источник правды — в [`docs/API.md`](docs/API.md).

```sh
# Собрать образ и поднять контейнер.
docker compose up -d --build

# Быстрая проверка.
curl -s http://localhost:8000/health
curl -s http://localhost:8000/api/v1/places | head
# затем открыть http://localhost:8000/ в браузере — откроется новый дизайн

# Остановить.
docker compose down
```

Новые места добавляются только в `data/geo/leninsky-poi-candidates.geojson` —
это единственный источник правды; `frontend-design/dist/data/` для границы и
точек-кандидатов больше не источник (сервер отдаёт эти два файла из `data/geo/`).

Автоматические тесты бэкенда (pytest + httpx TestClient, без сети) — в
одноразовом контейнере, без установки Python на хост:

```sh
docker run --rm -v "$PWD":/src -w /src/backend python:3.11-slim \
  sh -c "pip install -q -r requirements-dev.txt && python -m pytest -q"
```

Отдельный исторический предпросмотр карты открывается по [инструкции](docs/MAP_LENINSKY.md). Меры безопасности продукта в документах — требования, а не отчёт о внедрённых защитах всего приложения. Сейчас в репозитории есть `.gitignore`, шаблоны задач/PR, предпросмотр карты, дизайн-прототип и минимальный бэкенд; CI, защита ветки и продуктовая инфраструктура не настроены. Открытая лицензия кода пока не выбрана; геоданные OSM имеют отдельные [условия ODbL](data/geo/README.md).
