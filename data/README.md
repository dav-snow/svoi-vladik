# Каталог данных

Здесь будут храниться подготовленные вручную данные демо на 36 часов. Реальных карточек ещё нет. P0: 8 проверенных мест в одной компактной зоне, 2 прогулки по 3 точки, 1 квест на 3 точки и 3–5 памяток. 9–10 мест — только при свободном времени; до 3 актуальных событий — P1. Сокращённый вариант 6 мест/1 прогулка принимается явно, это не выполнение полного P0.

Перед добавлением записи прочитайте [правила проверки и список первичных источников](../docs/DATA_POLICY.md). API-контракт и окончательную структуру JSON команда согласует в [docs/API.md](../docs/API.md).

Отдельно подготовлена [географическая основа Ленинского района](geo/README.md): граница и три стартовых OSM-кандидата для предпросмотра. Они ещё `draft` и не заменяют проверенный каталог P0.

Сбором и редакторской проверкой занимается участник 3 — продакт-менеджер и редактор городского контента. Он передаёт таблицу мест и событий, тексты памяток и квеста с источниками. Бэкендер (участник 2) импортирует материалы в JSON и проверяет структуру; участник 1 совмещает дизайн и фронтенд и проверяет отображение. Писать JSON участнику 3 не обязательно. Состав таблиц и порядок передачи описаны в [ROLE_3.md](../docs/ROLE_3.md).

Предлагаемые наборы после согласования схемы:

- `places.json` — карточки мест для учёбы, творчества, встреч, отдыха, еды и туалета при подтверждённых условиях; `needs` маскота не заменяет проверку доступности.
- `walks.json` — 2 заранее составленные прогулки: порядок ID мест, примерная длительность, условия и проверка прохода.
- `guides.json` — памятки новичку, ответы статичного маскота и внешние транспортные ссылки.
- `quests.json` — сценарий квеста с привязкой к местам и проверенным историческим фактам.
- `events.json` — только P1: подтверждённые бесплатные события с временем, сроком актуальности и источником организатора; пустой массив допустим.

Чтобы не править одну таблицу одновременно, при старте согласовать будущие папки `data/content/` для исходников участника 3 и `data/examples/` для общих синтетических примеров участника 2. Машинные наборы импортирует участник 2; участник 3 проверяет содержание в общей сборке. Пока эти файлы/папки не созданы. Первые 3 карточки и одна точка квеста передаются к H4, остальное — частями.

Каждой записи нужны стабильный `id`, конкретный `source_url`, `checked_at`, `status` и срок перепроверки. Черновики не попадают в пользовательскую выдачу. Не добавляйте настоящие названия мест с выдуманными адресами, ценами или часами работы ради заполнения макета.

Для разработки допустимы отдельные синтетические фикстуры с очевидной маркировкой `demo`, без смешивания с проверенными данными. Они нужны для загрузки, пустых состояний и ошибок; на демо их следует называть тестовыми данными.

Текущие координаты посетителя, история перемещений, фотоотчёты и публичные отзывы в наборы P0 не входят. Аватар, прогресс и одна шапка локальны на устройстве; сервер не принимает их как подтверждённые достижения.

Карточка готова к публикации, когда человек сверил существенные поля по первоисточнику, записал дату проверки, проверил условия использования текста/медиа и перевёл её в `verified`. Для исторических фактов квеста нужна повторная проверка другим участником команды.
