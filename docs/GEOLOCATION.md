# Геолокация пользователя и поиск рядом

**Обязательная функция P0:** определить положение пользователя по его разрешению и показать ближайшие подходящие места **из проверенного каталога Ленинского района Владивостока**. Это уточнение плана: в репозитории есть отдельные предпросмотры карты и дизайна, интеграция геолокации для основного приложения ещё не реализована. Геолокация должна работать и в списке, независимо от доступности тайлов карты.

## Пользовательский путь

1. В «Я тут впервые» или у маскота показать кнопку **«Что рядом со мной»** и объяснение: «Используем местоположение для поиска ближайших мест. Историю перемещений не сохраняем».
2. По нажатию запросить одноразовую позицию через браузер. Пока запрос идёт, доступны «Выбрать точку вручную» и обычный каталог; разрешение не запрашивать при открытии сайта автоматически.
3. При успехе показать отдельный маркер **«Вы здесь»**, приблизительную точность и время последнего определения. Маркеры мест визуально отличаются; ручной старт подписан **«Выбранная точка»**, а не «Вы здесь».
4. Рассчитать расстояния до мест, применить интерес/потребность/бюджет и выбранный радиус, отсортировать совпадения от ближайшего к дальнему. В карточке — например «≈350 м по прямой»; расстояние приблизительное и не является длиной или временем пешеходного пути.
5. Смена радиуса или интереса пересчитывает список по уже полученной позиции без нового запроса геолокации. Карта и список используют один результат.
6. **«Обновить местоположение»** выполняет новый одноразовый запрос. **«Не использовать моё местоположение»** очищает позицию и её маркер в приложении, предлагает ручной старт; это не отменяет разрешение в настройках самого браузера.

Выдача охватывает только подготовленные 8 мест (либо согласованные 6/9–10), не все объекты поблизости. Пользователь может стоять в другом районе, но всё равно увидеть близкие места нашего каталога; административный район его позиции не определяем. Радиус не расширяет каталог на соседние районы.

## Техническое решение

Для веб-приложения достаточно `navigator.geolocation.getCurrentPosition`. На публичном стенде нужны HTTPS и разрешение пользователя; доступ также может ограничить `Permissions-Policy`. На H8 У2 проверяет настоящий HTTPS-стенд, У1 — вызов на телефоне, а не только внутри редакторского preview. [MDN: getCurrentPosition](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition).

Начальные настройки команды: `enableHighAccuracy: false`, `timeout: 10000`, `maximumAge: 60000`. Это выбор для демо, не гарантия точности или общего времени ожидания решения пользователя о разрешении. Повторное явное обновление использует `maximumAge: 0`. Бесконечные повторные запросы и фоновый `watchPosition` в P0 не нужны. Возможность ручного выбора остаётся доступной во время ожидания.

Во внутреннем состоянии клиента хранить только:

| Поле | Значение |
|---|---|
| `origin` | `device` либо `manual`; без выбранной точки — null |
| `lat`, `lng` | Конечные числа в допустимых диапазонах; не путать широту и долготу |
| `accuracyM` | Точность, сообщённая устройством, в метрах; для ручной точки null |
| `capturedAt` | Время определения позиции; ручной выбор не выдавать за измерение устройства |
| `radiusM` | 100–5000 м, по умолчанию 1000 м, как в [API.md](API.md) |

`accuracy` — оценка точности позиции в метрах, а не точность расстояния до каждого объекта. Показываем «Точность около … м». Если она больше выбранного радиуса, предупреждаем о приблизительном результате и предлагаем обновить позицию или выбрать точку вручную; фильтр не расширяется молча. Процент уверенности в UI не указываем. [MDN: accuracy](https://developer.mozilla.org/en-US/docs/Web/API/GeolocationCoordinates/accuracy).

Каталог приходит из существующего `GET /api/v1/places`; координаты и `accuracy` посетителя серверу не нужны. На клиенте вычисляем приблизительное расстояние по поверхности Земли (например, формулой хаверсинуса), в метрах; фильтр по неокруглённому значению `distanceM <= radiusM`, сортировка по возрастанию с устойчивым порядком по ID при равенстве. Округление применяется только к подписи в UI. Без точки расстояние не показывать, использовать обычный порядок каталога.

Отдельный геосервис, БД координат, авторизация, обратное геокодирование адреса пользователя и передача его позиции модели не требуются. Внешний навигатор открывается по клику с координатами выбранного места назначения. Его собственные запросы разрешений и расчёт маршрута приложение не контролирует.

## Ошибки и асинхронность

Состояния: `idle`, `requesting`, `ready`, `denied`, `unavailable`, `timeout`. Отсутствие API/HTTPS, отказ в разрешении и ошибка определения дают понятное сообщение и ручной старт; не подставлять центр района как будто это текущая позиция человека.

При пустом результате: **«В выбранном радиусе нет мест из нашего каталога Ленинского района»** → увеличить радиус в разрешённых пределах, изменить фильтр, выбрать старт вручную или посмотреть весь районный каталог. Пустая выдача не доказывает, что человек вне района: административного геозабора в P0 нет.

Не допускать, чтобы поздний ответ первого запроса заменил более новую позицию или ручной выбор. У1 хранит идентификатор актуального запроса и игнорирует устаревший callback после переключения режима/очистки/размонтирования. Положение хранится только в памяти текущей страницы, после перезагрузки начинается новое явное действие пользователя; прогресс квеста хранится отдельно.

## Приватность

Координаты, точность и время позиции не записываются в localStorage, URL, API, аналитику, логи, баг-репорты и публичные скриншоты. Сырой объект геолокации не сериализуется в сетевые запросы. Провайдер тайлов видит запросы области карты: об этом нужна краткая заметка, без обещания полной невидимости для третьих сторон. Остальные меры — [SECURITY.md](SECURITY.md).

## Кто реализует и что проверяет

- **У1:** запрос разрешения, состояния/ручной старт, маркер и точность, расчёт/сортировка/радиус, подписи, обновление и очистка позиции. Реализация в блоке H8–H10, без новой отдельной системы геоданных.
- **У2:** достоверные координаты мест в каталоге, API без передачи позиции посетителя, HTTPS/Permissions-Policy на выбранном хостинге, отсутствие геоданных в логах; помогает проверять интеграцию.
- **У3:** ручная приёмка на телефоне и синтетических позициях: разрешено/отказ/таймаут/нет API; одинаковые список/карта; сортировка; нулевое расстояние в точке места; изменение радиуса; нет совпадений; позиция вне района; низкая точность; ручной выбор во время запроса; обновление/очистка/перезагрузка. Синтетические позиции отмечаются как тестовые и не попадают в публичные доказательства реального местонахождения.

При проверке смотреть Network и хранилища браузера: запросы каталога не содержат позицию посетителя. Все проверки интеграции пока **не выполнены**: готового поиска рядом в основном приложении ещё нет. Пункт приёмки — G3 в [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).
