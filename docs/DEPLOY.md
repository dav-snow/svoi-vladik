# Деплой публичного стенда с HTTPS

Пошаговая инструкция для владельца. Репозиторий содержит только заготовки:
никто ничего не публикует за вас, реальные домены, IP и пароли в git не
вписываются. HTTPS обязателен: без него браузер не даёт геолокацию, а кука
входа с флагом Secure не установится — на телефоне не проверить ни вход,
ни «что рядом со мной».

Автоматизированный путь: `deploy.cmd` с Windows (через WSL) вызывает
`scripts/server-setup.sh` и `scripts/deploy-remote.sh` и делает шаги 3–6 за
вас. Ниже — те же шаги руками, чтобы понимать, что происходит.

## 1. Что нужно заранее

- VPS с Ubuntu и правом sudo (хватит 1 CPU / 1 ГБ RAM).
- Домен и A-запись, указывающая на IP сервера. Проверка: `nslookup ВАШ_ДОМЕН`
  должен вернуть IP сервера. Без своего домена подойдёт `<IP>.sslip.io`.
- Открытые порты 80 и 443 (Caddy получает сертификат через порт 80).
- Файл `data/private/quest-answers.json` с машины разработчика (см. шаг 4).

## 2. Установить Docker на сервере

Один раз на сервере (официальный скрипт Docker):

```sh
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # затем выйти и зайти по SSH заново
```

Либо выполните на сервере `scripts/server-setup.sh` — он ставит Docker из
официального репозитория и готовит каталог `/opt/svoi-vladik`.

## 3. Получить проект и создать .env

```sh
git clone https://github.com/dav-snow/svoi-vladik.git
cd svoi-vladik
cp .env.example .env
nano .env    # вписать свой DOMAIN и ACME_EMAIL
chmod 600 .env
```

`.env` в `.gitignore` — он остаётся только на сервере.

## 4. Перенести ключи ответов квестов (отдельный шаг!)

`data/private/quest-answers.json` — серверные ключи правильных ответов.
**В git и в Docker-образе этого файла нет.** Без него приложение работает,
но проверка ответов квеста отдаёт 503. Скопируйте файл с машины разработчика:

```sh
# с локальной машины, из корня проекта:
scp data/private/quest-answers.json ВАШ_ЛОГИН@СЕРВЕР:/opt/svoi-vladik/data/private/quest-answers.json
```

Путь на сервере должен совпадать с точкой монтирования из
`docker-compose.prod.yml` (`./data/private/quest-answers.json`).

## 5. Собрать и запустить

```sh
docker compose -f docker-compose.prod.yml up -d --build
```

Первый запуск занимает пару минут: сборка образа и получение сертификата.
Логи: `docker compose -f docker-compose.prod.yml logs --tail=50`.

## 6. Проверить

| Проверка | Ожидается |
| --- | --- |
| `curl https://ВАШ_ДОМЕН/health` | `{"status":"ok"}` |
| `curl -s -o /dev/null -w '%{http_code}' https://ВАШ_ДОМЕН/api/v1/places` | `200` |
| `curl -s -o /dev/null -w '%{http_code}' https://ВАШ_ДОМЕН/api/v1/quest` | `200` |
| Браузер: открыть `https://ВАШ_ДОМЕН/` | главная открывается, замок в адресной строке, сертификат валиден |

## 7. База данных: сохранность, бэкап, откат

Файл SQLite живёт на named volume `demo-data` (внутри контейнера —
`/app/storage/demo.sqlite3`), поэтому `up -d --build` и пересборка образа
его **не стирают**. Аккаунты и отметки пропадут только после
`docker compose down -v` (флаг `-v` удаляет volumes — не используйте его
по привычке).

Бэкап базы на сервере:

```sh
docker compose -f docker-compose.prod.yml cp api:/app/storage/demo.sqlite3 ./demo-backup-$(date +%F).sqlite3
```

Откат на предыдущую версию кода:

```sh
git log --oneline -5                 # найти рабочий коммит
git checkout <SHA>
docker compose -f docker-compose.prod.yml up -d --build
```

База при этом не трогается. Восстановление базы из бэкапа — та же команда
`cp` в обратную сторону и `docker compose -f docker-compose.prod.yml restart api`.

## 8. Если что-то не так

- **429 Too Many Requests** — сработал лимит частоты (вход/регистрация —
  10 в минуту, отметки и ответы квестов — 30 в минуту с одного IP).
  Подождите минуту (`Retry-After: 60`). Если 429 ловят разные посетители
  одновременно, проверьте, что api запущен с `--proxy-headers` и
  `--forwarded-allow-ips` из `docker-compose.prod.yml`, иначе все запросы
  считаются пришедшими с одного адреса прокси.
- **503 на ответах квеста** — на сервере нет `data/private/quest-answers.json`
  или его структура не совпадает с квестами. Повторите шаг 4 и
  `docker compose -f docker-compose.prod.yml restart api`.
- **Сертификат не выдаётся / браузер ругается** — почти всегда DNS или порт:
  A-запись домена не указывает на этот сервер (`nslookup ВАШ_ДОМЕН`), либо
  порт 80 закрыт файрволом. Исправьте и смотрите
  `docker compose -f docker-compose.prod.yml logs caddy --tail=50`.

## 9. Честные рамки демо-входа

На стенде демонстрационная авторизация: **нет email, восстановления пароля
и 2FA**. Забытый пароль не вернуть — только новый аккаунт. Не используйте
реальные пароли от других сервисов. Логин виден другим посетителям в
рейтинге. «Посещение» — это отметка пользователя, а не подтверждённый
визит; счётчики демонстрационные.
