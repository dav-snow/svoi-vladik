# Проверка перед показом и публикацией

**Сейчас это план: исходного кода приложения ещё нет. Все проверки ниже имеют статус «не проверено», а не «пройдено».** Список рассчитан на 36 часов и три роли: **1** — дизайн/фронтенд, **2** — бэкенд/размещение, **3** — продукт/контент/ручная QA/защита.

Географическая приёмка для G1–G3: все опубликованные места, точки прогулок, квест и возможные события находятся в Ленинском районе Владивостока и подтверждены редактором. Увеличение радиуса не добавляет другие районы; при отсутствии совпадений есть понятное сообщение и ручной старт внутри района. Проверка принадлежности конкретных объектов ещё не выполнена.

Участник 3 заполняет для проверяемых пунктов: фактический результат, commit SHA, среду/URL, дату, проверившего и ссылку на баг либо доказательство без секретов и GPS. Допустимые итоги: **пройдено**, **блокирует**, **не проверено**, **не применяется с объяснением**. Ожидаемый результат в таблице — условие приёмки, не отчёт о выполнении.

## Ранний технический стенд H8 и полное демо

**Технический стенд H8** может содержать только список и одну/несколько проверенных карточек с реальным API. Он помечен как незавершённый; отсутствие полного квеста и 8 карточек не мешает ранней интеграции. До открытия публичного URL У2 с У1 проверяют базовую защиту всех уже включённых частей: HTTPS, ограничение ввода/размеров/частоты и безопасные ошибки, отсутствие секретов/раздачи `.env`, безопасный вывод текста и ссылок, отсутствие отправки GPS, воспроизводимую сборку и способ отката. Это применимая часть G3–G10; У3 сверяет источники всех опубликованных записей и честную маркировку статуса из G2/G11. Не реализованные методы выключены либо отсутствуют, а не доступны без проверок. Наличие незавершённых функций не оправдывает публикацию небезопасного API.

**Полный допуск к демонстрации H27–33** требует G1–G11 и G12, если включён runtime-ИИ. Перед ним фиксируем заявленный объём: полный P0 (8 мест/2 прогулки) либо согласованный сокращённый вариант (6 мест/1 прогулка, при необходимости список вместо карты). Отсутствующие функции называются прямо; такой вариант не отмечается как выполнение полного P0. Таблица ниже относится к выбранной итоговой версии.

Проверки G5 и G7 выполнять на своей тестовой среде с контролируемыми фикстурами, без нагрузки на внешние сервисы. Численные пределы и детали реализации находятся в [SECURITY.md](SECURITY.md). Лимиты размера и времени, а также расходы внешних API требуют отдельных проверок. [OWASP API4](https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/).

Если один из G1–G11 не выполнен, нельзя отмечать итоговую версию готовой; G12 обязателен при включённом runtime-ИИ. Команда исправляет причину либо явно сокращает функцию и повторно проверяет затронутый путь. Выключение P1 позволяет выпускать P0 без G12. При отсутствии рабочего приложения можно показать макет или подготовленный сценарий, явно назвав его макетом; такой показ не считается успешным релизом приложения. Для раннего технического стенда действует отдельный допуск выше.

## Что можно перенести

Плавные анимации маскота, дополнительные шапки, звуки, аудиоистории, дополнительная палитра и расширение каталога сверх минимума можно отложить, если основной путь читаем и работает. Неработающая кнопка, скрытый текст ошибки, отсутствие клавиатурного фокуса, недоступный контраст основного текста или обязательная геолокация без fallback — ошибки интерфейса, а не украшения. Аккаунты, отзывы, чат, загрузки фото, мультиплеер, общий рейтинг и регулярные задания не входят в этот релиз.

## Будущие автоматические проверки

CI приложения пока отсутствует. После появления кода участники 1 и 2 добавят реальные команды и рабочие каталоги в README и workflow; до этого не вставлять зелёные бейджи и не отмечать несуществующие тесты пройденными.

- **Клиент:** установка по выбранному lockfile (`npm ci`, если выбран npm), проверка типов/линтера из фактического `package.json`, production build. Команду `npm run build` добавлять как проверку только после создания соответствующего script. Установка `npm ci` проверяет соответствие manifest и lockfile. [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci).
- **Сервер:** установка зафиксированных зависимостей, проверка запуска/health, небольшие тесты фильтров и публичной схемы, ошибок и связи квест/точка/вариант; тесты реально внедрённых лимитов и fallback, если включён P1. Точную команду запуска тестов записать вместе с этими тестами.
- **Каталог:** проверка схем, уникальности ID, ссылочной целостности, статусов и сроков, трёх точек каждого маршрута и трёх точек квеста. Автоматическая валидность не заменяет человеческую проверку исторических фактов и условий посещения.
- **Зависимости:** audit с сохранённым итогом разбора. Исправления через обновление lockfile и повторную сборку; `npm audit fix --force` не является обязательной или автоматической командой. [npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit).

После успешной автоматической проверки участник 3 всё равно проходит G1, G2, G3 и G11 на итоговой сборке. Статус «пройдено» относится только к зафиксированному SHA и среде; изменение кода, данных или размещения требует повторить связанные проверки.
