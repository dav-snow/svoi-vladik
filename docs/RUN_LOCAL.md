# Запуск на своём компьютере

Приложение и API открываются по одному адресу: **http://127.0.0.1:8000/**. Сервер слушает только локальный компьютер. Нужны доступный Node.js 20+ и Python с зависимостями проекта. Глобальные npm-пакеты, службы, активация окружения и изменение PowerShell ExecutionPolicy не требуются. Интернет нужен для внешней подложки карты, шрифтов и перехода в навигатор.

## Если окружение уже подготовлено

Откройте `start.cmd` двойным щелчком или выполните из корня проекта:

```text
npm start
```

Команда проверит окружение, запустит FastAPI и откроет фиксированный локальный адрес в обычном браузере. Оставьте окно запуска открытым. **Ctrl+C** останавливает сервер, запущенный этим окном. Сервер не устанавливается в автозапуск и не создаёт службу.

Если `npm` в PowerShell блокируется политикой скриптов, используйте **`npm.cmd start`** либо `start.cmd`. Менять ExecutionPolicy не нужно.

## Первый запуск: зависимости Python

Команды ниже выполняются из корня проекта в обычном терминале Windows. Все Python-пакеты устанавливаются только в `.venv`:

```text
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
npm.cmd start
```

Если команда `py` отсутствует, используйте `python -m venv .venv` в первой строке. Если Python вообще отсутствует, потребуется доступный Python 3.11+; скрипт запуска сам его не устанавливает. Уже созданную и работающую `.venv` заново создавать не нужно: достаточно второй команды для установки недостающих зависимостей.

Скрипт предпочитает `.venv/Scripts/python.exe` на Windows (`.venv/bin/python` на других системах). Если `.venv` нет, для обычного запуска он проверяет доступные `py -3`, `python` и `python3` и использует только интерпретатор, в котором импортируются `fastapi` и `uvicorn`. Если `.venv` существует, но повреждена или не содержит зависимостей, выдаётся понятная ошибка вместо незаметного переключения на другое окружение.

`npm install` для этого проекта не нужен: Node-скрипты используют стандартную библиотеку, npm-зависимостей и lock-файла нет.

На новом checkout отдельно подготовьте серверные ответы по [data/private/README.md](../data/private/README.md). Сам файл ответов исключён из публичного Git. В текущей локальной сборке он уже есть; повторно создавать его не нужно. Без конфигурации работают каталог и прогулки, но проверка квестов сообщает о временной недоступности.

## Проверки и сборка

```text
npm.cmd test
npm.cmd run build
```

`npm test` запускает `.venv` Python с `pytest backend/tests`, затем Node-тесты фронтенда (геолокация, маршрут, аватары, онбординг, motion); не открывает браузер и не стартует отдельный сервер. Для тестов нужна `.venv` с зависимостями из `backend/requirements-dev.txt`.

`npm run build` проверяет обязательные файлы интерфейса и серверных данных, корректность JSON, локальные ссылки HTML/CSS, синтаксис `app.js`, `mascot.js`, `sw.js` и отсутствие ключей ответов в публичных JSON. Приватный `data/private/quest-answers.json` проверяется как серверный файл и не копируется во фронтенд. После успешной проверки создаётся `frontend-design/dist/build-manifest.json` с размерами и SHA-256 публичных файлов. Этот манифест не содержит приватных ответов и не включает сам себя.

Фронтенд работает без компиляции: отдельная ZIP-сборка не нужна. Сборка не заменяет запуск сервера и тесты API. Запускайте её после завершения изменений данных и интерфейса; если обязательный файл ещё готовится, сборка завершится с именем недостающего файла.

Только проверить, без создания манифеста:

```text
node scripts/build.mjs --check-only
```

`--check-only` не пишет файлы, но теперь и сверяет `build-manifest.json` с содержимым `dist/`: если манифест устарел, проверка падает с перечнем изменившихся файлов. Именно поэтому в CI ловится забытая пересборка.

Браузерный смоук (нужен Edge/Chrome и уже запущенный сервер):

```text
node scripts/smoke-e2e.mjs
```

12 проверок: desktop/mobile без горизонтального скролла, синхронизация аватара
через аккаунт, кликабельная лицензия фото, manifest/SW, офлайн-оболочка.
Скриншоты складываются в `%TEMP%\svoi-vladik-smoke`. Скрипт создаёт один
демо-аккаунт в локальной базе, поэтому запускайте его против локального сервера.

Структурный аудит контента (границы, ссылки, фото, связи маршрутов и квестов):

```text
.venv\Scripts\python.exe scripts/audit_content.py
```

Полевую проверку входов, часов и цен он не заменяет — см.
[CONTENT_AUDIT.md](CONTENT_AUDIT.md).

## Без автоматического открытия браузера

```text
npm.cmd start -- --no-open
```

Этот режим подходит для QA. Адрес и проверка сервера остаются теми же.

## Занятый порт и повторный запуск

Скрипт признаёт существующий сервер нашим только при двух проверках: `/health` возвращает `status: "ok"`, а HTML главной страницы содержит `<meta name="application-name" content="svoi-vladik">`.

Если обе проверки прошли, повторный запуск использует уже работающий сервер, открывает адрес и завершается. Он **не останавливает** ранее запущенный процесс. Для остановки используйте Ctrl+C в окне, которое изначально запустило сервер.

Если порт 8000 занят другим приложением или проверка не прошла, скрипт сообщит об этом и завершится. Он не ищет процесс по порту и никого не завершает. Не убивайте неизвестные процессы ради запуска: остановите известное приложение его обычным способом.

## Пути с пробелами и кириллицей

Скрипты определяют корень проекта по собственному пути, а не по текущей папке терминала. Поэтому прямой вызов работает из другой папки:

```text
node "C:\путь с пробелами\Свой Владик\scripts\start.mjs" --no-open
node "C:\путь с пробелами\Свой Владик\scripts\build.mjs"
```

Для npm из другой папки используйте `npm.cmd --prefix "C:\путь к проекту" start`. Командный файл `start.cmd` сам переходит в свою папку.

Для общего доступа в интернете потребуется отдельное размещение. Локальный адрес не является опубликованным сайтом; запуск не меняет настройки брандмауэра и не открывает компьютер в локальную сеть.
