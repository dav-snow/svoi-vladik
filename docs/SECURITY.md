# Минимальная защита MVP

**Статус: план для разработки за 36 часов командой из трёх человек. Кода приложения пока нет; ни одна мера ниже ещё не подтверждена проверкой реализации.** Выпуск проверяется по [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md), поля API — по [API.md](API.md).

Ответственные: **1** — дизайн и фронтенд; **2** — бэкенд и размещение; **3** — продукт, контент, ручная приёмка и защита проекта. Участник 3 проверяет результат независимо от разработчика и записывает найденные ошибки.

## Границы P0

Полный P0: 8 проверенных мест (9–10 при свободном времени), две готовые прогулки по три точки; «Я тут впервые» с локальной геолокацией и выбором радиуса; один исторический квест на три точки; статичный маскот с тремя кнопками; локальный аватар и одна шапка-награда. Согласованный сокращённый вариант — 6 мест/1 прогулка с явной маркировкой; требования безопасности сохраняются. Публичный API читает подготовленный каталог JSON; база данных не нужна.

В P0 нет аккаунтов, отзывов, чата, загрузки фото, мультиплеера, общего рейтинга, ежедневных и еженедельных заданий. Не добавлять скрытые административные HTTP-методы или запись пользовательского контента. Редактор меняет каталог через проверяемый PR. Секреты runtime-ИИ понадобятся только при отдельном включении P1.

## Ввод и расход ресурсов — участник 2

Доверять ограничениям формы недостаточно: сервер проверяет тип, диапазон, длину и допустимые значения каждого поля. В FastAPI ограничения нужно явно объявить в схемах и параметрах; библиотека сама не выбирает ограничения продукта. [OWASP Input Validation](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html), [валидация параметров FastAPI](https://fastapi.tiangolo.com/tutorial/query-params-str-validations/).

Стартовые значения ниже согласованы для этого MVP; это решения команды, а не нормативные значения OWASP:

| Что ограничить | Планируемое правило | Ожидаемый отказ |
| --- | --- | --- |
| `id`, `stop_id`, `option_id` | От 1 до 64 символов ASCII, шаблон `^[A-Za-z0-9_-]+$`; затем проверка существования и связей | 422 при неверном формате, 404 при неизвестном ID; несовместимые квест/точка/вариант отклоняются |
| Фильтры | `interest`: `study`, `creativity`, `meet`, `rest`, `history`; `need`: `eat`, `toilet`, `fun`; `max_price_rub`: целое 0…100000 | 422 для неизвестного значения, отрицательного числа, дроби, лишнего или повторённого параметра |
| Размер запроса | Query string до 1024 байт; JSON-тело до 8 КиБ; только ожидаемые поля, без файлов и сжатых тел | 414 для длинного query, 413 для тела; 415 для неподдерживаемого формата, 422 для схемы |
| Частота | На IP: до 120 GET-запросов в минуту, до 30 ответов на квест в минуту | 429 с `Retry-After`; короткая понятная ошибка на клиенте |
| Время | Общий предел обработки API-запроса 10 секунд; ограниченные ожидание чтения и число одновременных соединений на выбранном хостинге | Запрос прекращается, клиент получает контролируемую ошибку и возможность повторить |
| Ответ | Ограниченный каталог, без пользовательского `limit` и неограниченных вложенных списков | Нет выдачи секретов, ключа правильного ответа или внутренних ошибок |

Лимит тела проверять на прокси/хостинге либо при потоковом чтении **до** накопления и разбора JSON. Одной проверки `Content-Length` недостаточно: тело может прийти без него. Для малого POST достаточно плоской схемы двух строк; не принимать произвольные вложенные структуры. Ограничивать также ресурсы и время обработки — отдельная мера от валидации полей. [OWASP Input Validation](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html), [OWASP API4: расход ресурсов](https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/).

IP для лимита брать из соединения или заголовка только доверенного прокси, а не из любого `X-Forwarded-For`. Для одного процесса допустим ограниченный по памяти счётчик с удалением старых записей; при нескольких процессах нужен общий лимит на прокси/хостинге. Проверить выбранную конфигурацию, а не заявлять, что она защищает от любого DDoS. IP для краткоживущего лимита не превращать в постоянную историю пользователя.

## Сеть, ссылки и вывод — участники 1 и 2

- Публичный фронтенд и API планируются через HTTPS. `localhost` допустим для разработки. В браузерах геолокация требует защищённого контекста и разрешения пользователя. [FastAPI: HTTPS](https://fastapi.tiangolo.com/deployment/https/), [MDN: Geolocation API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API).
- Предпочтителен один origin с `/api/v1`. Если фронтенд и API размещены отдельно, перечислить точные разрешённые origins и только используемые методы/заголовки; credentials в P0 не нужны. CORS управляет доступом браузерного JavaScript к ответу и не является авторизацией: сервер остаётся доступен прямому HTTP-клиенту. Поэтому проверки и лимиты действуют независимо от `Origin`. [FastAPI: CORS](https://fastapi.tiangolo.com/tutorial/cors/), [MDN: CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS).
- Текст каталога, квеста и будущего ИИ отображать обычными текстовыми узлами React, например `{description}`. Не использовать `dangerouslySetInnerHTML`, присваивание `innerHTML` или HTML-вставки в подписи карты. Отдельно проверить карту: сторонняя библиотека может принимать строку как HTML. Передача непроверенного HTML в React опасна. [React: HTML-вставки](https://react.dev/reference/react-dom/components/common#dangerously-setting-the-inner-html).
- Для `source_url`, регистрации и навигации принимать только HTTPS и точные hostname из проверенного командой списка; разбирать URL штатным парсером. Проверка `startsWith` или наличия слова в адресе не подходит. Отклонять `javascript:`, `data:`, логин/пароль в URL и неизвестный домен; ссылки создавать из проверенного каталога. Для новой вкладки задавать `rel="noopener noreferrer"`.
- Сервер P0 не скачивает страницы по URL от пользователя, не проксирует карты/картинки и не делает «предпросмотр ссылки». Источники — ссылки для перехода. Это сохраняет узкую сетевую поверхность; если загрузка URL когда-нибудь понадобится, её защита от SSRF требует отдельной реализации, включая адреса назначения и перенаправления. [OWASP: SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).

При хранении каталога в JSON SQL-запросов нет. Не добавлять СУБД ради этого MVP. Если позже появится SQL, значения передавать параметрами, а названия полей и сортировки выбирать из фиксированного списка; не собирать SQL строкой из ввода. Валидация не заменяет параметризацию. [OWASP: SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html).

## Геолокация и локальные награды — участники 1 и 3

«Я тут впервые» сначала объясняет назначение геолокации, затем по действию человека запрашивает разрешение. Расстояния до координат из каталога и фильтр радиуса рассчитываются в браузере. `lat`, `lng`, `radius` пользователя не нужны серверу, ИИ, аналитике или логам и не передаются туда. Отказ, таймаут и недоступность геолокации оставляют список мест и ручной выбор центра карты. Разрешение браузера не трактуется как согласие на публикацию местоположения. [MDN: Geolocation API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API).

Разрешённая позиция, её точность и время фиксации — только в памяти страницы; одноразовое обновление по кнопке, без фонового трекинга. Ручная точка не выдаётся за измеренную позицию; поздний callback не отменяет ручной выбор или очистку. Подробная интеграция и проверки — [GEOLOCATION.md](GEOLOCATION.md).

Не записывать точную позицию в `localStorage`, query string, отчёты об ошибках, скриншоты для GitHub или публичные ссылки. Во внешнюю навигацию приложение передаёт только выбранную точку назначения из каталога. Если сервис карты получает запросы тайлов для выбранной области, объяснить это в краткой заметке о приватности; не обещать, что внешняя карта вообще не видит запросов. Передача текущего местоположения или маршрута третьей стороне потребует отдельного понятного действия и согласия пользователя.

Прогресс квеста, выбранный аватар и одна шапка хранятся локально. При чтении хранилища проверять версию и допустимые ID; повреждённые значения сбрасывать без выполнения кода. Их легко изменить через инструменты браузера, поэтому это учебная награда без доказательства посещения и без общего рейтинга. Завершение квеста не требует фото, выхода за ограждения или опасных действий. Клиент не отправляет «баллы» как достоверное достижение серверу.

## Секреты, конфигурация и зависимости — участники 1 и 2

`VITE_*` попадает в клиентскую сборку; там допустим публичный адрес API, но не ключ ИИ, пароль или токен GitHub. Секретные значения нужны только серверу и хранилищу секретов хостинга. `.env`, `.gitignore` и пример с пустыми значениями уменьшают риск случайного коммита, но не делают опубликованный секрет безопасным. [Vite: переменные окружения](https://vite.dev/guide/env-and-mode).

Перед публикацией проверить diff, отслеживаемые файлы, клиентскую сборку и историю Git на секреты. Если ключ уже попал в коммит, сборку или лог: сначала отозвать/заменить его у провайдера, обновить размещение и проверить использование. Удаление строки в новом коммите не отзывает ключ и не очищает прошлую историю; необходимость очистки истории и порядок совместной работы обсуждаются командой отдельно. Переписывание истории не гарантирует удаления копий из форков и кэшей. [OWASP: отзыв и ротация секретов](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html).

Перед изменением конфигурации зафиксировать рабочий SHA и сохранить несекретный конфиг в Git; записать способ возврата прошлой конфигурации хостинга. Резервные копии реальных секретов допустимы только в защищённом хранилище команды/хостинга, вне публичной папки и репозитория. Каталог подготовленных мест в JSON — данные продукта; его не нужно прятать как секрет. Адрес API/провайдера и режим debug вынести в конфигурацию, ключи и пароли не встраивать в исходники.

План размещения: `.env` вне публично раздаваемого каталога; сервер без debug trace для посетителя; только нужные права процесса и токенов; каталог данных доступен приложению на чтение; нет публичных портов БД/панелей, которые не нужны MVP. Логи — метод, путь без координат/query, статус, длительность и технический ID; без тел запросов, ключей и точного GPS. Версионировать конфигурацию, схему, lockfile и инструкции восстановления **без секретов**; отдельно проверить восстановление каталога из Git. Принцип минимальных прав применяется и к секретам. [OWASP: Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html).

Название зависимости, предложенное ИИ, до установки сверять с официальной документацией проекта и реестром: существование, точное написание, владелец/репозиторий и назначение. Это наше правило против выдуманных имён и подмены пакетов (slopsquatting). Не запускать непонятную команду из ответа модели. Новые пакеты добавлять только при необходимости, изменения install-скриптов просматривать. Зависимости и версии фиксировать lockfile; чистую установку клиента выполнять по нему. [OWASP: цепочка поставки ПО](https://cheatsheetseries.owasp.org/cheatsheets/Software_Supply_Chain_Security_Cheat_Sheet.html), [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci).

Когда появятся зависимости, выполнить проверку известных уязвимостей для JavaScript и Python и разобрать результаты: версия, путь зависимости, достижимость проблемы, исправление, ответственный. Проверять также сборочные зависимости: они выполняются в процессе сборки. Сам по себе чистый audit не доказывает безопасность. `npm audit fix --force` не использовать как автоматический шаг: он может выйти за заданные диапазоны версий, включая несовместимые обновления. Обновление — через diff и повторную сборку/проверку сценария. [npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit).

## Дополнительные условия для runtime-ИИ — только P1

В P0 маскот работает тремя статичными кнопками и фильтрами; свободного чата и вызова модели нет. P1 включается только после готовности P0 и отдельной проверки:

1. Сервер отбирает подходящие подтверждённые записи. Модель получает ограниченный каталог и выбирает только существующие ID; её ответ проверяется по схеме и разрешённым ID. Тексты фактов и ссылки берутся из каталога, объяснение строится проверяемым шаблоном.
2. `query` — 1…500 символов; без GPS и необходимости писать личные сведения. Не давать модели инструменты для произвольных HTTP-запросов, выполнения команд или изменения данных. Текст пользователя и источников не становится системной инструкцией.
3. План лимитов: до 10 запросов в минуту на IP, один активный вызов модели на клиента, таймаут провайдера 8 секунд внутри общего лимита API 10 секунд; ограничение длины ответа и глобального бюджета провайдера. Конкретный денежный предел назначает команда до включения — пустое значение означает выключенный P1.
4. При таймауте, ошибке схемы, неизвестном ID, исчерпании бюджета или недоступности модели возвращается подбор по обычным фильтрам. Пустой каталог остаётся пустым. Отказ модели не блокирует карту, маршруты или квест.

Пока эти условия не проверены, runtime-ИИ выключен. Использование ИИ для дизайна, черновиков и разработки фиксируется отдельно и не означает наличие ИИ в работающем приложении.
