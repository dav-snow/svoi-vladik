# Безопасность демо

**Статус на 14 ноября 2026.** Ниже — фактическая проверка реализации, а не
обещание «production-ready». Независимый пентест, нагрузочные тесты и проверка
юристом не выполнялись. Демо публичное: регистрация открыта, данные аккаунтов
условные, не используйте реальные пароли.

## Что реализовано

| Область | Состояние |
|---|---|
| Пароли | `scrypt` (N=2^14, r=8, p=1), соль на пользователя, константное сравнение; для неизвестного логина считается dummy-хэш, чтобы не выдавать существование аккаунта |
| Сессии | случайный 256-битный токен, в БД только SHA-256, TTL 7 дней, удаление истёкших при входе; cookie `HttpOnly`, `SameSite=Lax`, в проде `Secure` (`COOKIE_SECURE=1`) |
| Выход | удаляет серверную сессию и cookie; чужой/просроченный токен даёт 401 |
| Ввод | Pydantic-схемы, ограничения длины/диапазона/шаблона, запрет лишних полей; query до 1 КиБ, JSON-тело auth/quest/me-write до 16 КиБ, только `application/json` |
| SQL | только параметризованные запросы; имена таблиц/полей не из ввода |
| Частота | 10 попыток входа/регистрации в минуту на IP и отдельно на логин, 30 POST-проверок/отметок/импорта в минуту на IP; ответ 429 с `Retry-After` |
| Доступ к данным | приватные ключи квестов не в Git и не в образе; `/data/private` и `/api/v1/map-data/...` — только allowlist; широкий mount `/data` удалён, публичны лишь два GeoJSON-маршрута |
| Сеть | один origin, CORS-заголовков нет; API наружу не публикуется, только Caddy 80/443; `--proxy-headers` доверяет лишь Docker-подсети |
| Заголовки | `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy`, `X-Permitted-Cross-Domain-Policies`; для `/api/*` — `Cache-Control: no-store`; CSP пока **Report-Only** |
| Transport | HTTPS и автоматический сертификат Caddy; HSTS `max-age=31536000` добавлен в `Caddyfile` (вступит после деплоя); `Server` upstream скрывается |
| Вывод | фронтенд строит DOM через `textContent`, без `innerHTML`/`eval`; внешние URL проверяются по HTTPS и схеме; опасные `javascript:`/`data:` отклоняются |
| Секреты | `.env`, `data/private/quest-answers.json`, SQLite исключены из Git и Docker-контекста; ответы квестов монтируются на сервере read-only |
| Контейнер | API и Caddy без публикации порта API; healthcheck; база на named volume |

Проверено тестами и вручную: `/data/private/*`, `/data/places.json`,
`/data/PRIVATE/*`, encoded-варианты и `/api/v1/map-data/quest-answers.json`
отдают 404; заголовки и `no-store` проверяются в pytest; вход/выход, 401/429,
размер тела и чужой Origin — в существующих тестах.

## Остаточные риски

1. **CSP только Report-Only.** Нужно проверить карту и шрифты на реальном
   телефоне, затем включить блокирующий режим. Сейчас он ничего не ломает, но
   и не защищает от инъекции.
2. **Импорт квестов доверяет клиенту.** `POST /me/quests/import` принимает
   ID завершённых квестов без ответов: это миграция локального прогресса.
   Пользователь может «заявить» любой квест и открыть косметический аватар.
   Для демо допустимо, для соревновательного продукта — нет.
3. **Лимиты в памяти одного процесса.** Uvicorn запущен одним worker; при
   масштабировании нужен общий лимит на Caddy/прокси. Распределённый перебор
   с многих IP не остановит.
4. **Нет CSRF-токена.** Защита держится на `SameSite=Lax`, JSON-only и
   отсутствии CORS; для текущих same-origin JSON-ручек этого достаточно, но при
   появлении form-encoding или сторонних клиентов нужен токен.
5. **Контейнер работает root.** Нужен non-root пользователь и проверка прав
   named volume; менять перед демо рискованно без миграции базы.
6. **Зависимости заданы диапазонами** (`fastapi>=…`, `uvicorn>=…`) и не
   проверялись `pip-audit`. Нужен lockfile и регулярный аудит.
7. **MapLibre с CDN без SRI.** Нужны `integrity`-хэши или локальная сборка;
   CDN остаётся доверенной стороной.
8. **Бэкапы не шифруются** и лежат на том же сервере; нет проверки
   восстановления. SQLite содержит логины и хэши паролей.
9. **TTL сессии 7 дней и scrypt N=2^14** — компромисс для демо; для production
   сократить TTL и поднять N (старые хэши продолжат проверяться, т.к. параметры
   хранятся в строке).
10. **Публичный топ раскрывает логины**, а регистрация открыта. Это заявлено в
    интерфейсе; не используйте личные логины.

## Что проверить перед «настоящим» запуском

- Включить CSP в блокирующем режиме после прогона карты/шрифтов/фото.
- Добавить SRI для MapLibre или раздавать его локально.
- Перевести API на non-root, проверить права volume и healthcheck.
- Зафиксировать зависимости lockfile, прогнать `pip-audit`/`npm audit`.
- Добавить CSRF-токен, если появятся формы/сторонние клиенты.
- Ограничить импорт квестов серверной проверкой ответов или убрать его.
- Настроить внешний rate-limit (Caddy/Cloudflare) и алерты.
- Проверить бэкап: шифрование, отдельное хранилище, восстановление на тестовом
  стенде.
- Провести независимый аудит и тест на утечки перед публичным запуском.
