# Задание третьему участнику на 36 часов

> **Исторический документ.** Задание вайбатона; текущее состояние и остатки —
> [STATUS.md](STATUS.md) и [BACKLOG.md](BACKLOG.md).

Твоя роль — **продакт и редактор городского контента с ручной приёмкой и подготовкой защиты**. Ты отвечаешь за то, какую задачу решает приложение, что оно показывает человеку и можно ли это убедительно продемонстрировать. Писать код необязательно. Участник 1 делает дизайн и фронтенд, участник 2 — сервер и техническое размещение.

## Первые результаты

В первые два часа прочитай правила вайбатона, уточни дедлайн, предложи один сценарий и согласуй с командой P0. Проведи 3 коротких разговора с новичками/первокурсниками; можно довести до 5, если остаётся время. Спроси о последнем реальном поиске места, трудностях и недостающей информации. ИИ может помочь с вопросами и сводкой реальных ответов; не придумывает собеседников и отзывы.

К H4 передай **первые 3 карточки и черновик одной точки квеста**. Не жди всего набора: разработчикам нужно сразу проверить формат и отображение. Работай в таблице и тексте; преобразование в JSON делает бэкендер.

## Каталог

Цель — **8 проверенных мест на одном компактном участке Ленинского района Владивостока**; 9–10 только в этом же районе и при свободном времени. Район уже выбран командой, на старте нужно определить только удобный участок внутри него. Подходящие типы: учёба, встречи/творчество, отдых/история; для кнопок маскота — проверенные еда, туалет и досуг. Не утверждай, что все категории есть в любой выбранной точке. Сокращённый вариант 6 мест принимается всей командой по контрольной точке, не молча.

Одна строка таблицы:

| Группа | Поля |
|---|---|
| Связь | `id`, название, категория, интересы, потребности `eat/toilet/fun`, краткое описание |
| Где | Адрес, широта `lat`, долгота `lng`; маркер соответствует адресу |
| Доступ | Цена либо «не уточнено», за что платят, условия бесплатности, часы либо «не уточнено», запись/ограничения |
| Проверка | Конкретная ссылка, издатель/название источника, `checked_at`, `checked_by`, `review_due_at`, статус, заметка о неизвестных сведениях |
| Связи | Памятки, прогулки и квест; ID выдайте один раз вместе с бэкендером |

Уточни бесплатность конкретного действия, а не учреждения вообще. Отсутствие цены не означает ноль. Сверяй факты с первоисточником по [DATA_POLICY.md](DATA_POLICY.md). Фото и чужие тексты без подходящих прав не добавляй. Реальные карточки нельзя заменять вымышленными записями без маркировки. События — P1: от 0 до 3 с подтверждением организатора и датами; пустой список честнее архивного анонса.

## Прогулки, квест и маскот

Подготовь 2 прогулки по 3 точки; точки могут пересекаться, одна прогулка связана с квестом. Для каждой передай название, короткое описание, порядок ID мест, приблизительную длительность, условия и дату проверки прохода. Собственного построения пути нет; линия между маркерами не подтверждает наличие прохода. Без осмотра проходов прогулка остаётся черновиком, а не готовым маршрутом.

Для каждой из 3 точек квеста: место → короткий факт и источник → отдельная художественная реплика персонажа → вопрос → 2–3 варианта → правильный вариант → пояснение. Другой участник повторно сверяет все факты. Задание не требует камеры, фотографии, опасных действий и входа в закрытое место. Квест и локальный прогресс не доказывают посещение.

Напиши 3–5 памяток по нескольку предложений для новичка. Маскот статичный: «Поесть», «Туалет», «Досуг» открывают фильтр и проверенную подсказку. Для неизвестных условий и пустого результата подготовь честный текст. Сложную личность персонажа, анимации и свободный чат сейчас не разрабатываем.

## Ручная приёмка

Начиная с первого общего экрана проверяй результат на телефоне: фильтр → карточка → источник → прогулка → внешняя навигация → квест → завершение. Дополнительно: отказ GPS, ручной старт, радиус без результатов, сбой API/карты, неверный ответ, перезагрузка с прогрессом и сброс. Геолокация не должна быть нужна серверу, а «радиус» не должен выдаваться за время пути.

Формат бага: **сборка/устройство → шаги → ожидалось → получилось → скриншот → влияние**. UI направляй участнику 1, API/импорт — участнику 2, неверный исходный контент исправляй в таблице. После исправления повторяй шаги. Безопасность сервера и техническое ревью выполняют разработчики; ты собираешь результаты по [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).

К H12 помоги решить, нужен ли сокращённый вариант. К H27 зафиксируй список функций и оставшиеся дефекты, не добавляй новые идеи к реализации. К H33 основной путь должен быть принят либо явно записан блокер. Несколько наблюдений за реальными пользователями полезнее большой выдуманной аналитики.

## Защита

Собери 5–6 слайдов: пользователь/проблема → единый сценарий трёх тем → что работает → демо → помощь ИИ и проверка человеком → результат проверок и следующий шаг. Подготовь рассказ на 3 минуты, запасную запись экрана и короткий список ограничений. Ты ведёшь рассказ, участник 1 показывает UI, участник 2 отвечает про сервер.

Журнал [AI_USAGE.md](AI_USAGE.md) заполняет каждый за себя, ты собираешь один показательный пример «задача → результат ИИ → правка человека → проверка». Не выдавай запланированные функции за реализованные. Подробное расписание и порядок обмена файлами — [IMPLEMENTATION_36H.md](IMPLEMENTATION_36H.md) и [PARALLEL_WORK.md](PARALLEL_WORK.md).
