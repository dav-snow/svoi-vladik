# API v1 для демо на 36 часов

**Исходный план контракта.** Реализованный API текущей сборки описан в [INTEGRATION.md](../INTEGRATION.md): 3–5 остановок, неизвестная длительность `null`, POST проверки ответа и завершения квеста. Координаты пользователя в API не передаются. Примеры ниже сохраняют историю планирования; при разработке сверяться с INTEGRATION и `/openapi.json`. Нет регистрации, публичных отзывов, загрузок, мультиплеера и SQL.

**География API — только Ленинский район Владивостока.** Выдача мест, прогулок, квеста и рекомендаций использует проверенный районный каталог. Район фиксирован для P0; выбор других районов и отдельный геосервис не нужны. Клиентский радиус только сужает этот каталог. При отсутствии результатов — пустая выдача с предложением выбрать старт в Ленинском районе, без автоматического расширения на весь город.

## Общие правила

- Стабильный ID: 1–64 символа ASCII `[A-Za-z0-9_-]`. Названия не служат ключами.
- Координаты места: `{ "lat": number, "lng": number }`, диапазоны −90…90/−180…180. Координаты посетителя API не принимает; радиус 100–5000 м, по умолчанию 1000 м, проверяется и вычисляется клиентом. Указано расстояние по прямой.
- `checked_at`/`review_due_at` — ISO 8601 с часовым поясом; времена событий P1 — с явным смещением, отображение `Asia/Vladivostok`.
- Источник: `source_url` и дополнительный `sources: [{ "title": "…", "url": "https://…" }]`. URL проверяет редактор, сервер валидирует схему/разрешённые домены. API не загружает произвольные URL посетителей.
- Статусы исходных данных: `draft`, `verified`, `needs_review`, `expired`, `archived`, `demo`. Публичная выдача — только `verified` с действующим сроком проверки; нет `demo` в реальном каталоге.
- Редакторские поля исходного набора: `source_title`, `publisher`, `checked_by`, `review_due_at`, `verification_note`. Их можно опустить в публичном ответе, но не источник и дату проверки.
- Цена: `price_rub: number | null` — минимальная подтверждённая стоимость выбранного действия, `price_note` — что включено и какие условия. Неизвестная цена не проходит фильтр бюджета. «Бесплатно» означает подтверждённые `0` и условия, не отсутствие данных.
- Один интерес на запрос: `study`, `creativity`, `meet`, `rest`, `history`. Потребность `need`: `eat`, `toilet`, `fun`. Не все места обязаны подходить под потребность.
- Ответы — данные, не готовый HTML; тексты отображаются безопасным текстовым рендерингом. Не переносить редакционные строки в HTML-попап карты.

## Методы P0

| Метод | Вход | Результат |
|---|---|---|
| `GET /health` | — | `{ "status": "ok" }`, без окружения/секретов |
| `GET /places` | `interest?`, `need?`, `max_price_rub?`: целое 0…100000 | `{ "items": Place[], "total": number }`; фильтры совместные |
| `GET /places/{id}` | ID | `Place` либо 404 |
| `GET /walks` | — | `{ "items": Walk[], "total": number }`, две готовые прогулки |
| `GET /walks/{id}` | ID | `Walk` либо 404 |
| `GET /guides` | `need?` | `{ "items": Guide[], "total": number }`, памятки маскота/новичка |
| `GET /quests` | `place_id?` | `{ "items": QuestSummary[], "total": number }` |
| `GET /quests/{id}` | ID | `Quest` с вариантами без ключа ответа |
| `POST /quests/{id}/answers` | `{ "stop_id": "…", "option_id": "…" }` | `{ "correct": true, "explanation": "…", "sources": [] }` |

Каталог маленький, пагинация и глобальный поиск не нужны. Клиент может один раз получить все места и локально применять радиус и потребности; результат локальных фильтров должен совпадать с серверными. При отсутствии совпадений HTTP 200 и пустой `items`. Нет кандидатов для кнопки маскота → пустой список и памятка, без выдуманного места.

Для «Что рядом со мной» клиент получает разрешённую позицию устройства, рассчитывает `distanceM`, фильтрует по радиусу и сортирует места от ближайшего к дальнему. Расстояние, точность и `capturedAt` — клиентское состояние, не новые поля запроса/ответа API. Определение позиции, ошибки и ручной старт описаны в [GEOLOCATION.md](GEOLOCATION.md). Для этого не нужен отдельный endpoint с геоданными пользователя.

## Форматы P0

### Place

Поля: `id`, `name`, `description`, `address`, `coordinates`, `category`, `interests: string[]`, `needs: string[]`, `price_rub`, `price_note`, `access_conditions`, `opening_hours: string | null`, `source_url`, `sources`, `checked_at`, `status`, `guide_ids: string[]`, `quest_ids: string[]`.

Для verified нужны реальные координаты, адрес, существенные условия, источник и дата. Часы/цена могут оставаться неизвестными с понятным сообщением; фильтр «открыто сейчас» не реализуем. `category` согласовать в SV-01; это редакционная категория, `interests/needs` — фиксированные словари. Ссылки между ID должны существовать и вести на опубликованные записи.

### Walk

`id`, `title`, `description`, `place_ids` (3 уникальных ID в нужном порядке), `estimated_minutes`, `route_note`, `route_checked_at`, `quest_id: string | null`, `source_url`, `sources`, `checked_at`, `status`.

Проверки импорта: все места verified, нет повторов внутри прогулки, длительность приблизительная и не обещает расчёт времени пути. Точки двух прогулок могут пересекаться. `route_checked_at` и редакционная заметка подтверждают осмотр проходов; без него не публикуем прогулку как готовую. `quest_id`, если задан, ссылается на существующий квест.

### Guide

`id`, `title`, `topic` (`transport` или `city`), `need: string | null`, `text`, `source_url`, `sources`, `checked_at`, `status`. Маскот использует готовые тексты и фильтр `need`, не сетевую модель. Изменяемые транспортные сведения сверяются заново перед показом.

### QuestSummary и Quest

`QuestSummary`: `id`, `title`, `description`, `estimated_minutes`, `related_place_ids`, `stop_count`, `source_url`, `sources`, `checked_at`, `status`.

`Quest` добавляет упорядоченный `stops` из 3 точек: `id`, `place_id`, `title`, `fact_text`, `fiction_text`, `question`, `options: [{id, text}]`, `sources`, `checked_at`. Каждый факт имеет источник; художественная часть явно обозначена. Правильный ответ и пояснение — в серверном наборе, не в выдаче квеста.

POST ответа проверяет принадлежность точки квесту и варианта точке. Неизвестные квест/точка/вариант — 404; неправильный известный вариант — 200 с `correct: false`. Повторять ответ можно. Клиент отмечает верный ответ, сохраняет пройденные точки и после всех трёх выдаёт локальную шапку. Сервер не хранит сессию и не утверждает физическое посещение; награда учебная, защиты от изменения localStorage нет. Это не база результатов для будущего общего рейтинга.

## Примеры для стыка

До H2 У2 добавляет общие JSON-примеры реального формата: место, прогулка, квест, правильный/неправильный ответ, пустая выдача, ошибка. У1 использует те же файлы как моки. Фикстуры с `demo-` и статусом `demo` не засчитываются в каталог. Минимальные общие ответы уже фиксируем здесь:

```json
{ "items": [], "total": 0 }
```

```json
{ "error": { "code": "NOT_FOUND", "message": "Запись не найдена" } }
```

## Ввод, ошибки и ограничения

Лимиты ниже — решения команды для небольшого демо, а не числа из стандарта. Обеспечить по [SECURITY.md](SECURITY.md) и проверить негативными запросами.

| Условие | Поведение |
|---|---|
| Неизвестный ID | 404 `NOT_FOUND`, без трассировки |
| Неверный тип, enum, ID/число вне границ, лишнее поле | 422 `VALIDATION_ERROR` |
| JSON body больше 8 KiB | 413 `PAYLOAD_TOO_LARGE`, до разбора; учесть поток без Content-Length |
| Query string больше 1024 bytes | 414 `URI_TOO_LONG` |
| POST без корректного `application/json` | 415 `UNSUPPORTED_MEDIA_TYPE` |
| Превышение частоты | 429 `RATE_LIMITED` и Retry-After; стартовые лимиты 120 GET/мин/IP и 30 answers/мин/IP |
| Временный сбой / таймаут | 503 `UNAVAILABLE`; серверный предел обработки запроса 10 с, не бесконечное ожидание |

Все ошибки приводятся к общей форме `error.code/message`; стандартный validation response FastAPI нужно явно адаптировать. Отладочный стек и подробные внутренние исключения остаются вне публичного ответа. IP за прокси брать только из доверенной инфраструктуры, не любого X-Forwarded-For. Клиент делает ограниченный повтор, а не бесконечный цикл.

## P1 вне обязательного пути

- **Замена точки:** клиент предлагает заранее проверенные кандидаты, не дублирует уже выбранные ID, хранит выбор локально. Проверить совместимость прохода; не обещать автоматический пересчёт. Если этого не проверили — не добавлять.
- **ИИ:** `POST /recommendations`, query до 500 символов, известные фильтры. Сервер сначала находит verified-кандидатов, модель выбирает только их ID; схему и принадлежность проверяет сервер. Ответ `{ "mode": "ai" | "filters", "place_ids": [], "quest_id": null, "reason": "…" }`; объяснение собирается по проверяемому шаблону. Нет кандидатов → пустая выдача. Таймаут модели 8 с, лимит 10 запросов/мин/IP и общий бюджет; при сбое — mode filters. Никакого выполнения инструментов, SQL и произвольного веб-доступа модели.
- **События:** `GET /events`, до 3 подтверждённых бесплатных предстоящих записей. `starts_at >= now`, `ends_at` либо редакторский `expires_at`, timezone, источник организатора, условия/регистрация и отмена. Неизвестное окончание не придумываем. Пустой массив допустим. Endpoint добавляем вместе с P1, не как блокер P0.

## Заморозка контракта

Владелец API — У2, клиентских типов — У1. Изменение имени/типа обсуждается до кода; в одном согласованном изменении обновляются контракт, примеры, сервер и клиент. При реализации сверить контракт с OpenAPI. H27 — заморозка функций, после неё только исправления несовместимости и ошибок.
