# API v0 — контракт для согласования

**Статус: проект, сервер ещё не реализован.** Контракт фиксируется бэкендером и фронтендером в SV-01 перед кодом. Базовый префикс `/api/v1`, формат JSON, UTF-8. Все примеры с `demo-` — синтетические, не настоящие места или события. В реальную выдачу они не входят.

## Общие правила

- `id` — стабильная строка, название не используется как ключ.
- Координаты — `{ "lat": number, "lng": number }`; нельзя менять порядок широты и долготы. В API данные, а не HTML.
- `checked_at` и `review_due_at` — момент проверки и срок следующей сверки в ISO 8601 с часовым поясом; время событий — ISO 8601 с `+10:00`, `timezone: "Asia/Vladivostok"`.
- `source_url` — основной публичный источник; `sources` — дополнительные источники с `url` и `title`. В исходных данных также хранится ответственный за проверку.
- `status`: `draft`, `verified`, `needs_review`, `expired`, `archived`, `demo`. Пользовательский API отдаёт только `verified` с действующим сроком проверки по правилам [DATA_POLICY.md](DATA_POLICY.md). В исходном наборе обязательны редакционные поля `source_title`, `publisher`, `checked_by`, `review_due_at`, `verification_note`; публичный ответ может опускать редакционные сведения, но сохраняет источник и `checked_at`.
- Цена: `price_rub` — минимальная стоимость выбранного сценария посещения или `null`, если не уточнена; `price_note` обязательно объясняет условия. Фильтр «бесплатно» включает только подтверждённый сценарий с `price_rub: 0`, бюджет — только известные цены не выше ограничения. Не обещать полную стоимость по минимальной цене.
- `interest` из словаря `study`, `creativity`, `meet`, `rest`, `history`. В первой версии один выбранный интерес на запрос.
- Пустой список — HTTP 200 и `items: []`. Неизвестный ID — 404; неверный ввод — 422; временная недоступность — 503.
- Ошибки привести к одному формату: `{ "error": { "code": "NOT_FOUND", "message": "Запись не найдена" } }`. Стандартные ошибки валидации FastAPI потребуется явно преобразовать.

## Методы P0

| Метод и путь | Вход | Выход |
|---|---|---|
| `GET /health` | — | `{ "status": "ok" }` без секретов |
| `GET /places` | `interest?`, `max_price_rub?` (целое ≥0) | `{ "items": Place[], "total": number }`; все условия применяются вместе |
| `GET /places/{id}` | ID места | `Place` |
| `GET /events` | — | `{ "items": Event[], "total": number }`, до 3 подтверждённых бесплатных предстоящих событий, по времени начала |
| `GET /guides` | — | `{ "items": Guide[] }` — памятки новичку |
| `GET /quests` | `place_id?` | `{ "items": QuestSummary[] }`; связь через `related_place_ids` |
| `GET /quests/{id}` | ID квеста | `Quest` с точками и вариантами ответа, без ключа правильного ответа |
| `POST /quests/{id}/answers` | `{ "stop_id": "…", "option_id": "…" }` | `{ "correct": true, "explanation": "…", "sources": [] }` |

Повторный ответ допустим; аккаунты и серверная сессия не нужны. Сервер валидирует, что точка и вариант принадлежат указанному квесту. После правильного ответа клиент отмечает точку пройденной; при неверном показывает пояснение и позволяет повторить. Это учебный квест без защиты от подсматривания. Известное время завершения события должно быть позже начала; API предстоящих событий использует `starts_at >= now`, исключает отменённые и неподтверждённые. Часы сервера сравниваются как абсолютное время.

## Модели

### Place

```json
{
  "id": "demo-place-001",
  "name": "Демонстрационное пространство — не реальный объект",
  "description": "Пример структуры карточки",
  "address": "Не задан",
  "coordinates": null,
  "category": "study_space",
  "interests": ["study", "history"],
  "price_rub": null,
  "price_note": "Стоимость не проверена",
  "access_conditions": "Условия нужно уточнить",
  "opening_hours": null,
  "source_url": null,
  "sources": [],
  "checked_at": null,
  "status": "demo",
  "guide_ids": [],
  "quest_ids": []
}
```

Для `verified` обязательны реальные координаты, адрес, подтверждённые условия, `source_url`, `checked_at` и непустой текст. `null` в примере не разрешает публиковать недопроверенную карточку. Часы работы могут оставаться неуточнёнными с явным сообщением. `category` — редакционная категория, `interests` — значения согласованного словаря. Поля `guide_ids` и `quest_ids` содержат только существующие связанные записи.

### Event

Поля: `id`, `title`, `description`, `place_id` (место из каталога), `starts_at`, `ends_at` (строка или null), `expires_at` (редакторский срок снятия, обязателен при неизвестном окончании), `timezone`, `price_rub` (для этой афиши 0), `price_note`, `access_conditions`, `registration_url` (строка или null), `source_url`, `sources`, `checked_at`, `status`, `cancelled` (boolean). При неизвестном окончании не обещать уложить событие в бюджет времени пользователя. Если событие нельзя достоверно связать с проверенным местом, сначала добавить и проверить место или не включать событие в MVP.

### Guide

`id`, `title`, `topic` (`transport` или `city`), `text`, `source_url`, `sources`, `checked_at`, `status`. Изменяемые транспортные сведения должны иметь источник; приложение не отдаёт расчёт времени прибытия транспорта.

### QuestSummary и Quest

`QuestSummary`: `id`, `title`, `description`, `estimated_minutes`, `related_place_ids`, `stop_count`, `source_url`, `sources`, `checked_at`, `status`.

`Quest` добавляет `route_note`, `route_checked_at` и упорядоченный `stops` (три элемента):

```json
{
  "id": "demo-stop-001",
  "place_id": "demo-place-001",
  "title": "Первая точка",
  "fact_text": "Текст факта после проверки человеком",
  "fiction_text": "Художественная реплика вымышленного проводника",
  "question": "Демонстрационный вопрос?",
  "options": [
    { "id": "a", "text": "Вариант A" },
    { "id": "b", "text": "Вариант B" }
  ],
  "sources": [],
  "checked_at": null
}
```

Поля `correct_option_id` и `explanation` хранятся в серверном наборе заданий; пояснение отдаётся после ответа. Источники факта доступны до ответа. Публикация квеста требует проверенных связей, источников и прохода маршрута; сам API не доказывает реальное посещение точки.

## Подбор с ИИ — P1

`POST /recommendations` принимает `{ "query": "хочу бесплатно поучиться", "interest": "study", "max_price_rub": 0 }`. Текст до 500 символов, без необходимости передавать личные сведения и геолокацию. Возвращает `{ "mode": "ai" | "filters", "place_ids": [], "quest_id": null, "reason": "…" }`.

Сервер сначала отбирает подходящие `verified` записи. Модель выбирает только ID из этого набора, сервер проверяет схему и принадлежность ID; факты отображаются из каталога. Для `reason` использовать проверяемый шаблон по интересу и цене, не свободный фактический рассказ модели. Некорректный ответ или таймаут → тот же контракт с `mode: "filters"`. Полное отсутствие кандидатов → пустая подборка, а не генерация новых мест. Ограничение частоты, таймаут и стоимость вызовов задаёт бэкендер перед включением P1.
