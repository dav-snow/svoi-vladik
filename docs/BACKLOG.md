## Ближайшие задачи

### 1. Задеплоить текущий `main` и проверить стенд

**Зачем:** публичный стенд отстаёт от `main`; на нём нет аватаров и нового
онбординга.

Критерий: `https://176-53-253-60.sslip.io/` отдаёт текущую сборку (`/app.js`
содержит `AVATAR_STORAGE` и `vlada-onboarding-seen`), `/health` — ok, фото и
квесты работают, проверено с телефона.

### 2. Подключить клиент к серверной синхронизации

**Зачем:** серверные ручки уже есть (`/me/avatars`, `/me/quests/import`,
запись завершений), но UI продолжает писать аватары и завершения только в
`localStorage`; на другом устройстве прогресс не виден.

Сделать (после редизайна GPT, чтобы не конфликтовать по `app.js`): при входе
читать `GET /me/avatars`, импортировать локальные завершения через
`POST /me/quests/import`, сохранять выбор через `PUT /me/avatars`, обновлять
счётчик после завершения квеста. ТЗ — `prompts/task-023-avatar-sync-ui.md`.
Критерий: завершённый квест и аватар видны после входа на другом устройстве;
сброс квеста не отнимает аватар.

### 3. Кликабельная лицензия фото в UI

**Зачем:** поля `credit`, `license`, `license_url` уже есть в API и данных, но
галерея показывает только подпись, без ссылки на условия.

Сделать: отрисовать автора, лицензию и ссылку на `license_url` в галерее
(делать после редизайна GPT, чтобы не конфликтовать по `app.js`). Критерий: в
карточке видны автор, лицензия и рабочая ссылка; тест на отрисовку/данные.

### 4. Полевая проверка контента

**Зачем:** все места, прогулки, квесты и гид — `draft`; источники сверены
онлайн, на местности — нет.

Критерий: проверены входы, часы, цены, доступность; обновлены статусы и
`checked_at`; спорные карточки скрыты или помечены. Владелец — участник 3.

### 5. E2E и визуальные регрессии

**Зачем:** 67 фронтовых тестов синтетические; браузерных сценариев и скриншот-
диффов в CI нет.

Сделать: Playwright/Cypress (или CDP-скрипт) для «главная → карточка → фото →
маршрут → квест», мобильный viewport, скриншоты в CI. Критерий: сценарий
проходит на 390×844 и 1440×960; падение ловится в PR.

### 6. Довести деплой и бэкапы до автоматизма

**Зачем:** скрипты `deploy-windows.ps1` и `backup-db.ps1` уже есть, но деплой
запускается вручную, а восстановление из бэкапа не проверено.

Сделать: GitHub Actions по тегу/ручному запуску с SSH-секретом (или оставить
скрипт, но описать в DEPLOY), ежедневный cron-бэкап, проверка восстановления
на стенде. Критерий: деплой одной командой, бэкап восстанавливается, откат
описан и проверен.

### 7. Доступность и клавиатура

**Зачем:** часть интерфейса проверялась только визуально.

Критерий: контраст AA, фокус видим везде, диалоги закрываются `Escape`,
тап-таргеты ≥ 44 px, экранный диктор проходит главный путь. Добавить
`aria-live` там, где меняется статус.

### 8. PWA и офлайн-минимум

**Зачем:** манифест и SW есть, но установка и офлайн не проверены.

Критерий: установка на Android/iOS, повторный запуск без сети показывает
оболочку и понятное сообщение; карта офлайн не обещается.

### 9. Производительность и вес

**Зачем:** фото-пак и карта — самые тяжёлые ресурсы.

Сделать: WebP/AVIF для фото, `loading="lazy"` (уже частично), проверка LCP на
телефоне, кеширование статики, лимит размера ответа `/places`. Критерий:
главная открывается на 3G/медленном Wi-Fi без «прыжков» и с читаемым текстом.

## Правила

- Одна задача — одна ветка и один PR; контракт API меняется вместе с клиентом,
  тестами и [API.md](API.md).
- Перед PR: `node --test frontend-design/tests/`,
  `pytest backend/tests`, `node scripts/build.mjs --check-only`,
  `git diff --check`.
- Нельзя ослаблять тесты и скрывать ограничения в текстах для пользователя.
